## 三、岛屿探索

### 3.1 探索形式
- 靠近岛屿时可选"探索"：船员小队自动横版闯关（玩家不操作，可观战，可点技能）
- 小队编成：**固定 3 人**（遗迹）/ 最多 3 人（其他岛型），从船员中拖拽选择
- **遗迹是 5 步探索**：外围 → 浅层 → 中层 → 深处 → 核心，每步 +20% 进度，**进度 100% 才结算通关奖励**
- **N1~N4 每一步都有「撤退」**（保留已得、放弃结算）；**N5 不可撤退且必有一战**
- **遗迹内不死亡**：HP 归零 = 倒地 → **判负按"撤退"收场**（同伴把你拖回船），不死不伤
- **撤退与判负的区别**（这条决定玩家敢不敢走第 5 步）：
  - **主动撤退**（N1~N4 第三选项）：**0 遗失**，已拾取全带走，只放弃"通关结算"
  - **判负**（全灭/45s 超时）：**普通材料与贝壳币遗失 30%**；**装备/图纸/强化石/技能书/橙装碎片 0 遗失**
- 判负结算界面**先报"遗失了部分物资"，再报"带回了什么"**——顺序反过来会被当成系统吞奖励
- 关卡产出：木材/铁/食物/药材等基础材料 + **主题独占产出**（图纸/紫装/技能书/橙装碎片/强化石）
- **7 主题 × 5 节点 × 2 选项 = 70 条已全部配完**，完整流程、8 张配表、9 种结果类型见《03-MVP内容配置表》§3.3

### 3.2 自动扫荡

#### 3.3.1 竞技场岛（v1.4 无限层；**v1.20 已落表**：`11_竞技场.xlsx` 5 张表 + 事件 `P01` 入口 + 池条目 `320108`）

**定位：全作唯一"零风险、有时间就能打"的纯战斗场所，也是强化石的主要来源。**

| 项 | 规则 |
|---|---|
| 上场 | 1~3 名船员（不能全员——船还要有人开） |
| 层数 | **无限，`n ≥ 1`** |
| 历史最高层 | **到达过的最深层**（含挑战失败那层），字段 `arena_max_layer`，只增不减 |
| 起点 | 每次进入从 **`max(1, 历史最高层 − 3)`** 开始 |
| 保底 | 起点起 **3 层**为「回溯层」（都已通过过），**保底结算这 3 层奖励** |
| 回溯层结算 | 奖励 **×40%**，**不给强化石、不给装备** |
| 新层结算 | 从历史最高层往上，首通 **100%** |
| 对手 | **其他玩家最强 3 人镜像**（v1.20）：历史最高层 **±3 层**窗口内选取，属性/外貌/名称/装备/技能全来自真实快照；窗口内不足 5 名用**虚拟船长兜底**（虚拟层 ±3 内均匀取 → 锚点公式生成属性，名字取 100 假名池、外貌按 05 外貌表 roll）。契约见《11_竞技场.xlsx》 |
| 难度 | `对手属性 = 基准属性(n) × 0.85`，`基准属性(n) = 100 × 1.11^(n−1)`（**兜底虚拟船长的生成公式**，镜像制下它退居平衡锚） |
| 死亡 | **不会死亡**。HP 归零判负，回船后恢复至 30% |
| 消耗 | 每场 **食物 = 上场人数 × 3**；**无进入次数限制** |
| 失败 | 立即结束，已得奖励 **100% 保留**，**历史最高层不变** |
| 产出 | 币（`180×1.09^(n−1)`）+ 材料 + **强化石**（`2+floor((n−1)/5)`，封顶 6） |

**为什么难度不能用"玩家上场均值 × 系数"（旧方案）**

那是死锁：玩家战力涨 30%，对手同步涨 30%，比值不变——**玩家永远过不了下一层，层数进度会永久冻结在第 1 周的水平**。旧方案只做 10 层，这个洞没暴露；一旦改成无限层，它第一天就会爆。

**正解是锚定层数，不锚定玩家**：`基准属性(n) = 100 × 1.11^(n−1)`，1 点 = 第 1 章开局标准船员（主属性 4~8）的单人四维合计。**`1.11` 不是拍脑袋**——奇迹之海每 5 层一档，怪物按 `1.75^(n-1)` 外推（决策 #32），`1.75^(1/5) ≈ 1.119`，取 1.11，正好和主线成长对齐。

| 层 | 对手战力 | 对应进度 | 目标通过率 |
|---|---|---|---|
| 1 | 85 | 第 1 章开局 | 95% |
| 5 | 129 | 第 1 章末期 | 70% |
| 10 | 217 | 第 2 章中期 | 60% |
| 15 | 366 | 第 2 章末期 | 60% |
| 20 | 617 | 第 3 章末期 | 55% |
| 25 | 1,040 | 奇迹之海第 2 层 | 50% |
| 30+ | `85×1.11^(n−1)` | 每 5 层 ≈ 奇迹之海 1 层 | 45~55% |

**为什么无限层不会变成无限刷（三道软闸，没有一道是硬限制）**

1. **回溯层 ×40% 且不给石/装备** → 单次回溯 3 层约 200~300 币，折合 80 币/分钟，**低于推图的 210 币/分钟**。刷它不如推图。
2. **每场吃食物（人数 × 3）** → 3 人队打 3 场 = 27 食物。食物是产能，不是白给。
3. **新层过不去就是过不去** → 想多拿只能变强；变强靠推图和强化，不靠竞技场。

> **一句话定位**：竞技场是**把"战力"换成"强化石"的兑换机**，不是产出机。币收益低于推图（不抢主线时间），但强化石只能在这里稳定拿（变强必须来）。
> **界面必须显示三样东西**：层数标尺（金线标历史最高层）、本次进度（哪几层是回溯/哪层是新）、对手预览（职业 + 主属性 + 装备品质）。**不要做排行榜**——单机排名没有意义，做了反而暴露它是假的。

#### 3.3.2 海面奇遇（v1.4 定结构，**v1.10 已全部落表**）

**旧版的问题是"跟推图没有区别，只是更碎"**：20 条全是拿点木材/拿点币/SAN 加减，玩家会本能地忽略它（直接点"离开"，因为看文本要花时间）。

**v1.4 改成三选一：正解（看清了，付代价拿稀有材料）／ 误判（贪心或粗暴，触发战斗）／ 退出（安全，无收益）。**

**它同时是 6 种海面专属稀有材料的唯一来源**（深渊鳞 / 鲸脂 / 星砂 / 虚空晶 / 龙骨木 / 海图残页）——**不进商店、不掉落、不可锻造产出**。其中两条是刻意的卡点材料：**虚空晶可替代赎罪券清负面特性**、**龙骨木是船体 Lv5 的必需料**。这让"不打海面奇遇"在中后期变成一个真实的损失。

| 项 | 规则 | 落表位置（v1.10） |
|---|---|---|
| 触发 | 航行中按距离偶发：**平均 150 里一次**（`jitter 0.4`，开局 60 里后开始） | `01/关卡事件触发规则表` **10108 / 20107**（`event_category=choice`） |
| 结构 | 20 条 = 4 类 × 5（海况 / 生物 / 人造物 / 超自然） | `01/事件表` **2101~2105 / 2201~2205 / 2301~2305 / 2401~2405** |
| 选项 | **每条三选一**：正解 / 误判 / 退出。误判必须"看起来更赚" | `01/事件选项表` **60 行**（`node_id` 全空——choice 不走节点） |
| 稀有材料 | **只从"正解"产出**；误判打赢战斗只给普通材料 + 币 | `01/事件结果表` **61 个结果组**；`03/物品表` 6 条 `sm_*` |
| 属性判定 | 部分正解需 技巧/智力/精神 ≥12。**判定失败退回"退出"档结果，不触发战斗** | 4 条带 `check` 的选项，`result_fail` 统一指 `RS-SEA-NOTHING` |
| 退出 | **免费，不扣任何东西**（低挫败红线） | C 档 = `result_type=close` + **不建结果组**，结构上不可能扣东西 |
| 误判战斗 | 5 个 1 波组（8101~8105），`hp_scale=dmg_scale=0.9` | `02/怪物组表` + `03/掉落组表` **4020（杂兵）/ 4021（精英）** |
| 事件池 | 一个池全海域共用，20 条等权 | `01/事件池表` **3103** + 20 条池条目 |

> **为什么"误判"要看起来更赚**：如果坑一眼就是坑，玩家不会选，三选一形同虚设。**要骗到才有博弈。**
> **为什么判定失败不罚战斗**：判定失败已经是惩罚，再加一场战斗会让玩家觉得"练了属性反而更亏"，进而干脆不选正解——**这就把设计目的打反了**。
> **编号为什么是 21xx/22xx/23xx/24xx 而不是 SW01**：岛屿已占 `W01`（沉船「奥菲莉亚号」），再造 `SW01` 会让所有按前缀匹配的地方互相污染。纯数字号段让"21xx 一定是海况奇遇"可断言。
> **条目级 SSOT 在《03-MVP内容配置表》§3.5**（含 20 条全文、6 种材料清单与对账表），本文档只定义结构与红线。

> 这一条同时解决了《02》§6.1 算出来的"+10% 盈余"该往哪去：**常规消耗口吃掉 90%，剩下 10% 由玩家自己决定要不要买神秘商店的高价货。** 低于 0 会让玩家不敢赌，高于 25% 会让钱变成数字。

> 问题有两处：① 落难船员 20% × 612 次/周 = **122 名船员**，远超船员池上限（约 20），供给完全失灵；② 5 个品类无法表达"木箱/铁桶/水桶/宝箱/浮尸"的差异，玩家每次点击看到的都是同一件事。

**现行结构（三层，详见《03-MVP内容配置表》§四）：**

```
漂流物触发（每 50 里）
  → 第 1 层：抽大类（10 类：木材18/金属12/食水16/弹药8/财货8/装备6/船员4/宝箱8/危险10/杂物10）
  → 第 2 层：类内抽模板（39 条）
  → 第 3 层：roll 数量 = 模板区间 × (1 + 0.35 × (海域-1))
  → 独立判定：特殊池 7 条，合计 9.3%
```

| 关键量（供本文档的资源来源表对账） | 一周次数 |
|---|---|
| 漂流物总触发 | 612 |
| 其中 船员类（G，4%） | 24 次 → **实际可用约 15 人** |
| 其中 财货类（E，8%） | 49 次 → 约 4,500 贝壳币 |
| 其中 弹药类（D，8%） | 49 次 → 约 1,100 发 |
| 其中 装备类（F，6%）+ 宝箱类（H，8%） | 86 次 → 装备主来源之一 |

> **落难船员从 20% 降到 4% 是必须的修正**，不是削弱福利：船员池上限只有约 20 人，一周供给 122 人等于"招募系统不存在"。降到 4%（约 15 人/周）后，"漂流物给免费但低质（四维 4~8）、酒馆给收费但高质"这条分工才成立。

### A.3 关卡事件触发规则表（核心重设计）

**替代旧"统一事件池"模式**，改为每条规则独立触发。一条规则 = 一类事件的完整触发逻辑。程序同时维护多条规则，各自独立计时/计距触发。

**三种触发机制：**

| trigger_type | 触发方式 | 参数含义 | 典型事件 |
|---|---|---|---|
| time | 独立计时器，平均 avg_value 秒触发一次 | avg_value=秒数，interval_jitter=±抖动 | 怪物袭击（独立于航行距离） |
| distance | 每次航行移动后，按累计距离与间隔判定 | avg_value=距离，interval_jitter=±抖动 | 漂流物 / 岛屿 |
| milestone | 航行距离达到**固定值**时强制触发一次 | avg_value=固定距离值，interval_jitter=0 | **精英怪（固定距离点）** / 关卡 Boss |

> **决策 #35**：精英怪升为与 Boss 同级的 milestone 固定距离点（第一章 @400 和 @800），不再用 distance 概率触发。这样关卡节奏感更强，玩家能预期"走到一半会刷精英"。奇迹之海无限模式仍用 distance 触发精英。

**avg_value + interval_jitter 的实际间隔计算：**

```
实际间隔 = avg_value × random(1 - interval_jitter, 1 + interval_jitter)
# 例：avg_value=60, jitter=0.5 → 实际间隔在 30~90 秒之间随机
#     avg_value=200, jitter=0.4 → 实际间隔在 120~280 距离之间随机
# milestone 类型：interval_jitter=0，start_distance=end_distance=固定距离点
```

### A.3.5 航段（检查点）——长章节的中断方案

**3,000 里 / 5,000 里的章节必须能中断**，否则单次上线打不完一章，玩家会弃坑。

| 项 | 规则 |
|---|---|
| 航段长度 | **每 500 里为 1 个航段**；第一章 2 段、第二章 6 段、第三章 10 段 |
| 段内时长 | ≈ **8.3 分钟**（500 秒） |
| 存档点 | 每完成一个航段，自动写入"已抵达航段 N" |
| 主动抛锚 | 任意时刻可点"抛锚休整"，进度存到**当前航段起点**（本段进度丢弃） |
| 下线 | **自动抛锚**，进度存到当前航段起点；下线不推进距离（见《01-系统总览》§5.5 离线规则） |
| 战败 | 章节进度重置到**当前航段起点**，不是整章重置（这是 v3.0 的重要放宽） |
| 段内加速 | 已通关的航段可"全速航行"跳过，节省 60% 时间（重刷用） |

> **战败只回退一个航段（8 分钟），不是整章（83 分钟）**。这一条直接决定了长章节能不能成立：整章重置在 5,000 里的关卡里等同于"惩罚 83 分钟"，没有任何玩家能接受。

### A.3.6 章节时长核算（内容量测算的锚点）

```
距离推进速率 = 航速 × 全局系数 dist_per_speed = 0.1
基础航速 10 → 1.0 距离/秒
第一章 1,000 秒 ≈ 16.7 min；第二章 3,000 秒 ≈ 50 min；第三章 5,000 秒 ≈ 83 min
```

| 项 | 第一章 | 第二章 | 第三章 | 合计 |
|---|---|---|---|---|
| 总距离 | 1,000 | 3,000 | 5,000 | 9,000 |
| 总时长 | ≈ 17 min | ≈ 50 min | ≈ 83 min | **≈ 150 min（2.5h）** |
| 小怪遭遇次数 | 8 | 27 | 50 | 85 |
| 精英/小Boss/大Boss | 3 | 6 | 9 | 18 |
| 战斗总时长 | ≈ 2 min | ≈ 7 min | ≈ 13 min | ≈ 22 min |
| 战斗占比 | 12% | 14% | 16% | **15%** |
| 平静期总时长 | ≈ 15 min | ≈ 43 min | ≈ 71 min | ≈ 129 min |
| 航段数 | 2 | 6 | 10 | 18 |

> **12~14% 的战斗占比是故意的**。章节变长但节拍不变——仍然是"每 100 秒被咬一口，剩下时间收拾"。变长的是**收拾的时间**，这正是经营层的空间。
> 每 100 秒窗口的动作密度保持不变（捞漂浮物 3~5 次、抛竿 1~2 次、拖人 2~4 次）。章节从 17 分钟拉到 83 分钟，拉长的是"有多少次这样的窗口"，不是"每个窗口有多忙"。

### A.3.7 奇迹之海（level_id=201）无限循环与深度层

| 项 | 规则 |
|---|---|
| 地形/事件池 | **循环复用第一~三章的地图资源**：层 1 用第一章池、层 2 用第二章池、层 3 用第三章池、层 4 回到第一章池，依此类推 |
| 层长度 | **每层 1,500 里**（≈25 分钟） |

| 怪物池 | 层 n 的怪物取自对应海域池（层4 起复用海域1~3 的怪，但数值是层4 的） |
| 精英 | 层内 `distance` 触发，avg=250 里，jitter 0.3 |
| 小Boss | 每层中点（750 里处）1 个 |
| 大Boss | 每层末尾（1500 里 × layer）1 个，用层对应海域的 Boss |
| 中断 | 每 500 里一个航段，与主线一致 |
| 死亡/战败 | **不重置层进度**，只回退到最近航段；这是无限模式能反复刷的前提 |

> **深度层是"无限内容"的唯一低成本解法**：不新增任何美术、不新增任何关卡，只靠 `layer` 一个变量驱动数值成长。玩家在层 8 面对的是"数值=海域8、模型=海域2"的怪——感知上是"更深的海，同样的怪物变得更可怕"，这恰好符合克苏鲁的恐怖逻辑。

**程序执行伪代码：**

```python
# 关卡开始时，为每条触发规则初始化一个计时器/距离计
for rule in level.rules:
    rule.accum_time = 0          # time 类型用
    rule.accum_distance = 0      # distance 类型用
    rule.next_trigger = jitter(rule.avg_value, rule.interval_jitter)
    rule.triggered_count = 0

# 航行循环
while not reached_end:
    ship.move(...)  # 航行一段距离 delta_dist
    current_distance += delta_dist

    for rule in level.rules:
        if rule.max_triggers and rule.triggered_count >= rule.max_triggers:
            continue
        if current_distance < rule.start_distance: continue
        if rule.end_distance != -1 and current_distance > rule.end_distance: continue

        if rule.trigger_type == "time":
            rule.accum_time += delta_time
            if rule.accum_time >= rule.next_trigger:
                _fire_event(rule); rule.triggered_count += 1
                rule.accum_time = 0
                rule.next_trigger = jitter(rule.avg_value, rule.interval_jitter)

        elif rule.trigger_type == "distance":
            rule.accum_distance += delta_dist
            if rule.accum_distance >= rule.next_trigger:
                _fire_event(rule); rule.triggered_count += 1
                rule.accum_distance = 0
                rule.next_trigger = jitter(rule.avg_value, rule.interval_jitter)

        elif rule.trigger_type == "milestone":
            if current_distance >= rule.start_distance:
                _fire_event(rule); rule.triggered_count += 1

    if current_distance >= level.total_distance:
        # 关卡结束；force_trigger_at_end 但还没触发的 milestone 规则强制触发
        for rule in level.rules:
            if rule.triggered_count == 0 and rule.force_trigger_at_end:
                _fire_event(rule)
        break

def _fire_event(rule):
    # 从事件池里按权重抽 1~N 条
    pool = load_pool(rule.event_pool_id)
    ids = weighted_pick(pool.entries, pool.min_picks, pool.max_picks)
    for target_id in ids:
        dispatch(rule.event_category, target_id)
```

### B.3 怪物组波次表（塔防式出生）

**start_delay 语义**（v4 起变更）：相对**上一波开始时间**的偏移秒。`wave1=0`，波间统一 2s 间隔 → `wave2=2, wave3=4, wave4=6, ...`（等差 2s）。

程序执行：按 group_id 取出所有 wave，按 wave_index 分组排序；每个 wave_index 可能有**多行**（一波内 1~2 种怪物各自独立 spawn）；到达 start_delay 时间点后，该 wave_index 的所有行同时开始按 `spawn_interval=0.2s` 逐个生成怪物（数量固定，`count_min=count_max`）；所有怪物清完才进下一波。

**wave_role 标记语义**：`vanguard` = 前置小怪波 / `main` = 收尾波（精英/Boss 出场，或小怪组最后一波）。

程序按顺序遍历掉落组条目：

| entry_type | 执行规则 | 适用场景 |
|---|---|---|
| **guaranteed** | **100% 必定执行**，roll `count_min~count_max` 的数量，**执行 roll_times 次** | 固定掉的东西：贝壳币、基础资源 |
| **weight** | 同一掉落组 mode=all 时，weight 条目之间先**归一化权重**，再**按权重抽 N 条**（N=1 或同组 guaranteed 条目数）；mode=pick_n 时按 pick_min~pick_max 统一选 | 随机出哪个：Boss 给两张图纸选1，或资源池选1~2种 |
| **independent** | 每条**各自**用 probability 判定，可多条同时中，**执行 roll_times 次** | 概率给装备/转职书：15%概率出锻造材料组 |

**mode 字段决定整组行为：**

| mode | 行为 |
|---|---|
| all | 每条 guaranteed 都执行；weight 条目在同组内统一权重归一化后抽 N 条；independent 各自独立判定 |
| pick_n | **忽略 guaranteed**；仅 weight 条目，按 pick_min~pick_max 从全部 weight 条目里选 N 条 |

### C.3 主链掉落配置示例

**普通战斗（drop_group_id=4001）：**

```
[guaranteed] 50~150 贝壳币                 ← 100%必掉
[guaranteed] 引用子组 4011（基础资源池）     ← 100%必掉，子组内部按权重选1~2种
[independent 15%] 引用子组 4012（锻造材料池）← 15%概率再掉1种锻造材料
```

**Boss 战斗（drop_group_id=4003）：**

```
[guaranteed] 800~1200 贝壳币                ← 100%必掉
[guaranteed] 装备池（随机武器）              ← 100%必掉1件武器
[weight]   图纸A（权重60）vs 图纸B（权重40）  ← 按权重给1张
[independent 25%] 转职书                    ← 25%概率额外出1本
```

### C.4 掉落组嵌套

条目表 `target_type=sub_group` 时，`target_id` 指向另一个掉落组，程序**递归**执行子组：

```
4001 普通战斗掉落
  └── sub_group 4011 基础资源权重池（mode=pick_n, pick_min=1, pick_max=2）
       ├── wood  weight=40, count=3~6
       ├── iron  weight=35, count=2~4
       ├── stone weight=15, count=2~3
       └── food  weight=10, count=2~4
```

程序先从 4001 执行 guaranteed 贝壳币 → 遇到 sub_group 4011 递归进去，执行 pick_n 选 1~2 种资源各给 count_min~count_max 件 → 回到 4001 继续处理独立概率条目。

### C.5 图纸系统

船只与高级船舱升级需要图纸。图纸来源：

| 来源 | 方式 |
|---|---|
| Boss 掉落 | 掉落条目 weight 60/40 按权重给 |
| 神秘宝箱 | 漂浮物掉落组 independent 10%概率 |
| 商人购买 | 商店商品池 room_blueprint 类型 |

升级时程序检查：消耗的通用消耗表 `cost_id=4` 是否包含图纸 item_id；包含 → 升级，不包含 → 拒绝并提示"需要建造图纸"。

## 程序接入说明（v1.25：`01_海域与关卡.xlsx` + `11_竞技场.xlsx`）

### 数据源与加载顺序

`01_海域与关卡.xlsx`（11 sheet）与 `11_竞技场.xlsx`（5 sheet）。加载顺序：**海域表 → 关卡表 → 触发规则表 → 事件池表/池条目表 → 事件表 → 事件选项/节点/结果表 → 商店两表**；11 表在关卡数据之后加载（P01 事件 `ref_id` 指向竞技场界面，不依赖其数值）。

### 核心键与流转

| 表 | 主键 | 说明 |
|---|---|---|
| 关卡事件触发规则表 | rule_id | `trigger_type`：`time`（avg_value=秒）/`distance`（avg_value=航行距离）/`milestone`（start=end=固定距离，触发 1 次）；`interval_jitter` 为 ±比例抖动；`start_distance` 前不触发；`max_triggers=0` 表不限次；`force_trigger_at_end=1` 强制在关卡终点前结算 |
| 事件池表/条目表 | pool_id / entry_id | 池类型：raid/float/island/elite/boss/event；抽取 = **按 weight 加权随机**，`min_trigger_level` 为玩家进度门槛 |
| 事件表 | event_id | `type`：battle/choice/float_obj/shop/pvp/recruit/island；`ref_id` 按 type 分发（battle→怪物组、float_obj→掉落组、shop→shop_id、pvp→竞技场界面）；`auto_resolve=1` 漂浮物碰到即结算；`san_delta` 事件级 SAN 变更 |
| 事件选项表 | option_id | `check` 属性门槛（`attr>=8` 格式）；`result_type=result_group` 指向结果组；`result_fail` 为判定失败分支 |
| 事件节点表 | node_id | 遗迹探索：seq 顺序推进，`progress_add` 累计进度，`can_retreat` 允许系统生成撤退选项 |
| 事件结果表 | group_id（**同 id 多行，按 seq 顺序执行，勿 dict 化**） | `type`：item（`item=xxx;qty=n`，**qty 允许为负**）/equip（`pool=2;qty=1`→装备掉落权重表）/equip_pool/sub_group（嵌套掉落组，`roll_times` 多次）/progress/san/roll（`chance=0.5;hit=RS-xx;miss=empty`）/battle/shop |

### 商店（随机商店表 + 商店商品池）

- 货架：从商品池按 `weight` 抽 `item_slot_count` 条；免费刷新 `free_refresh_count` 次，之后走 `refresh_cost_id` 或广告（`ad_refresh_enabled`）
- 定价：`price_type=shell` 固定价直接用 `price_value`；`price_scale=2`（random_weapon）→ **程序按品质系数动态计价**（卖店价 ×2）
- 库存：`stock_min~stock_max` 每次刷新重 roll（0~1 即"稀有上架"）；`sell_back_enabled=1` 支持卖出（回收价=物品表 `sell_price`）

### 竞技场（`11_竞技场.xlsx`）

- 层数锚点表：段内**线性插值**（表只给每 5 层锚点）；`base_attr=100×1.11^(n−1)` 为缺省公式，`opponent_attr=base×0.85`
- **对手镜像制**：读玩家镜像契约表字段（uid/船长名/当前层/最强 3 人快照），候选窗口 = 历史最高层 ±3 层内玩家，随机 5 名；不足 5 名用虚拟船长兜底（虚拟层在 ±3 内均匀取 → 按锚点公式生成属性，名池抽取，外貌按 05 船员外貌表 roll）
- 首通奖励：币 `180×1.09^(n−1)`、强化石 `2+floor((n−1)/5)` 封顶 6；失败不惩罚，回溯 40% 层数不发石装

## 程序接入说明（v1.25：`03_物品与掉落.xlsx`——掉落引擎通用）

### 数据源

4 sheet：物品表（全游戏道具字典）→ 掉落组表 → 掉落条目表 → 装备掉落权重表。**掉落组是全游戏通用结算器**：关卡通关、Boss、事件结果、钓鱼（08 有独立同构表）都指向它。

### 掉落组抽取算法（条目三种类型混排）

按 `entry_type` 分三步执行：

1. **guaranteed**：必给。按 `count_min~count_max` roll 数量，`roll_times` 重复整个条目（如 4011 材料子组 roll 18 次）
2. **weight**：组内所有 weight 条目按权重抽 `pick_min~pick_max` 个
3. **independent**：每条独立按 `probability` 判定（可全中可全不中）

`target_type`：`item`（target_id=item_id）/ `equip_pool`（→装备掉落权重表）/ `sub_group`（嵌套掉落组，递归）。`min_trigger_level` 为关卡门槛。

### 装备掉落权重表

复合键 (equip_drop_id, quality_id, slot)：先按 equip_drop_id 选池（1=白蓝常驻、2=蓝紫 Boss、3=紫装保底 5~7 品质），再按 slot 权重定部位、quality 权重定品质、`tier_range` 定位阶。

### 物品表约定

`use_effect` JSON 现仅两键：`trigger_event`（藏宝图 → 2004）、`random_blueprint`（蓝图合成产物，程序从未拥有图纸池中等权随机，全拥有补偿 150 币）。`sell_price=0` = 不可回收（任务材料）。

组 `4010` 为故意跳号**不得配置**；`4004` 为 v1.1 预留空壳**必须无条目**；删掉的旧蓝图 `bp_engine_1`/`bp_chapel_1` 不得再引用。
