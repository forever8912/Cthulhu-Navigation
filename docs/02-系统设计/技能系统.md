# 《恐惧之海》微信小游戏版 - 技能系统

> 版本：v1.3（2026-10-28，**主线 8 只精英/小Boss 补齐独享主动+被动（6141~6156 / buff 4310~4321）；技能表 66 条**）
> 定位：**技能的 SSOT**。本文只回答“技能从哪来、什么时候触发、怎么叠加、怎么占出手”。伤害/治疗/减伤公式一律回《战斗系统》，属性来源一律回《角色系统》。
> **v1.2 改了什么**：① 技能表加 `summon_id` / `summon_count` 两列，**召唤从 buff 改回技能字段**（buff 4217 删除，见下方说明）；② 三只终章 Boss 各加一条「HP<30% 二阶段」专属技（`6131`/`6132`/`6133`）。
>
> **v1.1 改了什么**：① `skill_scope` 加 `monster`，号段加 6xxx；② 新增 `trigger_param` 一列（`hp_below` 阈值 / `on_hit` 概率）；③ `trigger_cond` 加 `on_apply` / `on_death` / `hp_below`；④ `power_ratio` / `cd_ratio` 补怪物语义（**相对该怪 attack / attack_interval_base**）；⑤ buff 表 `buff_scope` 加 `monster`、号段加 42xx、`effect_json` 新增 11 个 key；⑥ 见附录 A.5。
> 红线：**武器/转职技能玩家不手动释放**，全部自动触发。玩家手点的只有《战斗系统》第七章的 2 个全船技能（全员参战 / 传送逃跑），高频操作仍是拖拽船员。

## 一、技能三分法

| 类型 | 来源 | 触发方式 | 解锁条件 |
|---|---|---|---|
| 被动 | 转职 | 常驻，无出手 | 转职位阶（核心 2 档获得，逐档升级） |
| 平A | 武器自带 | 按武器释放间隔 | 能装备该武器 |
| 主动 | 武器自带 | CD 好了**替换下一次平A** | 武器的职业系 + 最低位阶 |

**硬规则**
- 技能不另建一套伤害体系：所有伤害/治疗都走《战斗系统》3.1/3.9，技能只提供“武器效果值、倍率、目标类型、附加效果”
- 技能不改变释放效率公式；释放间隔仍由武器的 `效率属性 ÷ 效率需求` 决定
- 每名船员同时生效的被动上限 **4 条**（核心 1 + 分档新增 3），避免后期面板膨胀
- 武器决定“怎么打”，职业决定“打得多好”：武器给主动/平A，职业给被动

## 二、技能配置字段

| 字段 | 说明 |
|---|---|
| id / 名称 / 图标 | 配置表主键 |
| 类型 | passive / normal（平A）/ active（主动） |
| 归属 | 被动=职业系+位阶；平A/主动=武器 id |

## 三、转职被动

### 3.1 叠加结构：核心升级 + 分档新增

| 位阶 | 获得 | 规则 |
|---|---|---|
| 2 档 | 核心被动 | 随位阶覆盖升级（条目不变，数值提升） |
| 3 档 | 新增被动 1 | 独立条目 |
| 5 档 | 新增被动 2 | 独立条目 |
| 7 档 | 新增被动 3 | 独立条目 |

- 满阶共 4 条：核心（2→7 档共升级 5 次）+ 3 条新增
- 升级是**覆盖**，不是叠加：7 档不会同时存在“核心Lv1+Lv2+…”，只保留当前档数值
- 与特性系统互不替代：特性是随机获得的 3 正 2 负，被动是转职确定的成长

### 3.2 被动作用域（只允许三类）

| 作用域 | 示例 | 上限建议 |
|---|---|---|
| 增伤/治疗类 | 法器伤害+8%、治疗量+10% | 单条 ≤15%，四条合计 ≤40% |
| 效率/暴击类 | 器械房间效率+8%、暴击率+8% | 不突破 200% 效率封顶 |
| 抗性/生存类 | 恐惧伤害-15%、SAN上限+10% | 不突破 SAN 抵抗 60% 封顶 |

> 禁止“固定攻击力+N”这类绕过属性模型的被动；一切加成都必须落在已有公式的乘区里。

## 四、平A 与主动

> **术语区分（v2.1 补充）**：本章的"主动"是**武器自带、自动释放**的技能——走出手队列，玩家不点、也不占额外操作。
> 玩家手动点击的只有《战斗系统》第七章的两个**全船技能**（全员参战 / 传送逃跑），两者不共用冷却、不互占出手、不叠加倍率。改数值时不要把两套混算。

### 4.1 出手队列（关键规则）

每个船员只有**一个出手队列**，按 `释放间隔` 计时：

```
计时到点：
  主动CD已好 → 释放主动，进入CD；本次不释放平A
  主动CD未好 → 释放平A
```

- 主动**不额外占出手**，而是顶替一次平A；因此不会出现“白送一份DPS”
- 主动占全部出手次数的比例 ≈ `释放间隔 ÷ 主动CD`
  - 例：释放间隔1s、CD10s → 每10次出手有1次是主动，主动占 **10%** 次数
- 因此主动强度可给到平A的 2~3 倍，全期DPS提升约 **+10%~+20%**，不会失控
- 圣典的治疗也走同一队列：CD未好时执行平A（治疗或缺损目标则待机）

### 4.2 平A（每把武器必带）

| 武器类别 | 平A示例 | 结算 |
|---|---|---|
| 近战 | 挥砍 | 物理单体 |
| 枪械 | 射击 | 物理单体，射程远 |
| 法器 | 魔法飞弹 | 魔法单体 |
| 圣典 | 祈祷 | 对友方治疗；对亡灵才转为伤害 |

### 4.3 主动（每把武器 0~1 个，橙装可带独有主动）

示例：**火焰法杖**（法器·火系）

| 项 | 内容 |
|---|---|
| 职业门槛 | 魔法与知识之神系，位阶 ≥2（魔法师） |
| 平A | 魔法飞弹：单体魔法，效果值=武器伤害 |
| 主动 | 火球术：CD 10s，范围魔法，最多 3 目标，效果值=武器伤害×2.2 |
| 范围衰减 | 第1/2/3目标分别 100% / 60% / 40% |

- 主动单次倍率锚点：平A 的 **2.0~3.0 倍**
- 范围技能必须配目标上限与衰减，否则群怪 TTK 崩塌
- 主动可以带治疗/护盾/净化（如圣典“群体祈祷”），但仍受 `单次治疗 ≤ 目标HP×30%` 的硬上限

## 五、武器职业门槛

### 5.1 门槛字段

| 字段 | 说明 |
|---|---|
| 职业系要求 classLine | 七神系之一（见《船员养成系统》4.2） |
| 最低位阶 minTier | 1~7；不满足则不可装备 |
| 主动技能 id / CD | 无主动则留空 |

- 不满足时武器显示为灰色，提示“需 魔法与知识之神系 · 2档”
- 转职后立即解锁，不需要额外道具
- 换武器 = 换平A与主动，切换不消耗资源（沿用装备槽规则）

### 5.2 武器池规模控制

- 每条职业系**每位阶只配 1~2 把专属武器**；不要按“职业×武器类别×稀有度”铺满
- 无职业锁的通用武器只给白/蓝品质，不抢职业特色
- 橙装可带独有主动，作为该职业系的毕业目标

### 5.3 掉落与职业匹配

- 职业专属武器在掉落时，若队伍中存在该职业系船员，权重提升（避免“掉了一把没人能用”）
- 该规则是掉落表权重修正，不改《装备与锻造系统》的70/30配比

## 六、数值自检

1. **主动占比**：`释放间隔 ÷ CD` 即主动次数占比；CD 越短占比越高。建议 CD ≥ 8s，且不低于释放间隔的 5 倍
2. **主动收益**：主动倍率2~3倍、占比10% → 总DPS +10%~20%；超过 +25% 需回调倍率
3. **被动总量**：满阶4条，单条 ≤15%，合计 ≤40%，与词缀增伤 ≤100% 分开计
4. **范围技能**：≤3目标，衰减 100/60/40；精英与Boss默认只吃单体（避免AOE逃课）
5. **职业锁**：专属武器到手时，队伍应已有可达位阶的船员，否则该掉落无意义
6. **不引入**：技能等级、技能点、手动释放、技能书抽卡
7. **与特性区分**：被动确定获得（转职），特性随机获得（结算），两者不互相顶替

# 附录 A 配置表设计：技能表（`05_船员与技能.xlsx` Sheet3，v2 已生成）

> v2 核心变更（2026-10-27）：**技能表只存"比例+目标规则+buff挂载"，属性判断层剥离到武器/房间**；CD/强度都用相对比例（不再写绝对秒/绝对值）；被动整体移到 buff 表；目标维度拆为敌我 side + 形态 shape 两列；新增 trigger_cond 支持 on_hit/on_kill 等触发时机。

## A.1 技能表字段（v2 重构）

| 字段 | 类型 | 控制内容 |
|---|---|---|
| skill_id | [int] | 唯一 id。号段：1xxx=武器平A / 2xxx=武器主动 / 5xxx=房间与船体技能 / **6xxx=怪物**（6001 近战物理平A / 6003 魔法平A / **6101~6123 主线主动技·按海域共用（基础动作）** / **6131~6133 三只终章 Boss 二阶段专属** / **6141~6156 主线 8 只精英/小Boss 独享技（偶=主动、奇=被动）** / 62xx 遗迹被动，xx=enemy 后两位 / 63xx 复合被动的第二条） |
| name | [string] | 技能名（挥砍/火球术/鱼叉穿刺/生命藤条/迷雾缠绕/神的眼睛·凝视…） |
| skill_scope | [enum] | crew=船员（平A/主动） / room=房间与船体 / **monster=怪物**。三者走同一条伤害管线，差别只在"强度基准是谁" |
| skill_type | [enum] | normal=平A（按武器释放间隔触发）/ active=主动（顶替一次平A）/ trigger=触发类（挂载在 buff 上，如 on_kill 回血） |
| power_ratio | [float] | **强度比例**：平A=1.0，主动/房间技能=N 倍武器/房间强度；**怪物技能=N 倍该怪 `attack`**（《02》怪物等级表）。最终伤害 = 基准强度 × power_ratio × 目标衰减。**技能表不关心基准强度来自哪个属性**（那是武器/房间/怪物等级的事） |
| cd_ratio | [float] | **CD 比例**：船员相对武器释放间隔（平A=1.0、主动=3.0~5.0）；房间独立计时=0；**怪物相对 `attack_interval_base`**——同一技能挂在 interval=2.0s 的精英上是 12s，挂在 2.5s 的 Boss 上就是 15s，**天然随怪自适应，不需要按只配 CD**。绝算：`实际CD = attack_interval_base × cd_ratio` |
| target_side | [enum] | 敌我：enemy=敌方 / ally=友方 / self=自身 / all_rooms=全船房间（房间 buff 扩散） |
| target_shape | [enum] | 形态：single=单体 / aoe=圆形范围 / line=直线 / cone=扇形 |
| target_max | [int] | 范围/直线/扇形命中上限 ≤3（房间炮可>3）；单体写 1 |
| falloff_json | [json] | 范围衰减 `[1.0,0.6,0.4]`（按距离排序）；单体写空 |
| trigger_cond | [enum] | **触发时机**：cast=释放时（默认）/ **on_apply=持有者入场即挂载（纯被动，怪物常驻特性用这个）** / on_hit=命中目标时 / on_hit_being=被命中时 / on_kill=击杀时 / on_cast=自己施法时 / **on_death=死亡时（溅墨/爆炸/亡者馈赠）** / **hp_below=血量低于阈值触发一次** / self_turn_start=自身回合开始 / room_start=战斗开始 / room_damaged=房间受损时。平A/主动=cast；触发类按实际配 |
| trigger_param | [float] | **触发参数**（v1.1 新增）：`hp_below`→阈值（0.5=半血）/ `on_hit`→触发概率（0.2=20%）/ `cd` 类不用填（CD 走 cd_ratio）/ 其余留空。**这是从旧"怪物技能表"并进来的唯一一个新字段**，因为阈值/概率必须有地方落 |
| buff_ids | [list] | **挂载的 buff id 列表**（按 \| 拆，引用 buff 表）。例如"自我修复"房间技能：无直接伤害，但 buff_ids=`4001`（buff 表配 duration=0, trigger=room_damaged, effect=每秒恢复1%）。**怪物技能的附加效果（减伤/闪避/SAN 侵蚀/护盾/增伤）都走这里**——技能只负责"打谁、多疼、多久一次" |
| summon_id | [int] | **召唤物 `monster_id`**（引用《02》怪物表），空=不召唤。**v1.2 新增** |
| summon_count | [int] | **召唤数量**，与 `summon_id` 同填同空 |
| desc | [string] | 说明 |


> **为什么召唤要单开字段，而不是塞进 buff 的 `effect_json`**（v1.2 的决定）：
> ① **语义不对**。buff 是"持续状态"，有 `duration` / `tick_interval` / `stack_limit`——这三个对召唤全是废字段；召唤是**一次性动作**，放完就完，跟"打一发火球"同类。
> ② **原设计有硬伤**。旧 `buff 4217 召唤` 的 `effect_json` 写死了 `{"summon":{"monster_id":"101","count":2}}`，海域3 的 `6122` 想召幽灵海盗 `303` 只能靠**程序在施加时改写 effect_json**——需要靠运行时打补丁才能跑通的设计，就是设计错了。
> ③ **会重复触发**。buff 挂在身上后，只要 `hp_below` 判定仍成立（比如怪自己回血又掉下去），就会反复施放，等于无限刷怪。走技能字段则由 `trigger_cond` 管一次性。
>
> **召唤的触发条件必须是"跨阈值一次"**：`trigger_cond=hp_below` + `trigger_param=0.5` 表示**血量首次跌破 50% 时放一次**，程序需记录已触发标记，血回升再掉也不再放。这条同样约束 `6131`/`6132`/`6133` 三个二阶段技。

## A.3 首章内容与号段规划

## A.5 怪物技能为什么并进这张表（v1.1）

> 原先 `02_怪物与战斗.xlsx` 自带一张 `怪物技能表`（6 列效果枚举：aoe / debuff_hit / summon / heal…）。那等于**第二套技能体系**——同一个"范围伤害"在船员侧叫 `power_ratio + target_shape`，在怪物侧叫 `effect_type=aoe + effect_value`，改一个数值要动两处，加一个新效果要改两个枚举。**v1.8 已删除该表**，怪物技能全部并入本表。

**三条硬规则**

1. **怪物表只存 id**：`02_怪物与战斗.xlsx` 的 `怪物表.skill_ids` 存 `6001|6101|6102` 这样的列表，不存任何技能参数。遗迹怪的被动同样写在这个列表里（`701|6201` 形式）——**v1.9 删掉了 `island_enemy` 表**，遗迹怪本来就是 `02/怪物表` 的 701~763，那张表只是同一批怪的 HP/攻击副本。
2. **被动效果一律过 buff**：技能的 `buff_ids` 指向 buff 表，buff 表 `buff_scope=monster`。**怪物表与 buff 表之间没有直接引用，中间必须隔着技能表这一层。** 想给某只怪加个"受远程减伤"，改的是它引用的技能，不是它自己。
3. **按档配基础动作 + 按只配招牌技**（v1.10 修正）：主线同海域的精英/Boss **保留**一组 61xx 主动技作为「基础动作」（保证每只怪都有稳定的输出节奏，也让新怪接入成本低），**再各挂 1 条独享主动 + 1 条独享被动**（6141~6156）。遗迹则沿用 `62xx`（`xx` = enemy 后两位）的纯按只配。**48 只怪引用 66 条技能中的 54 条**（128 处引用），无孤儿技能。
   > **为什么不全换成独享技**：一只怪 5~6 条主动技在 3v3 同屏里轮转不过来，玩家读不出「这只怪的特点」。保留 1~2 条海域共用技当「背景噪音」，独享技才能真正被感知——**差异感来自对比，不是来自数量**。
   > **换色变体必须跟随本体**：208（204 换色）、310（304 换色）的技能表与本体**完全一致**，否则「换色」这个 0 成本变体就变成了「另一只怪」，等于凭空多两份设计债。

**`attack_type` 与平A技能的对应关系**

| attack_type | 首条技能 | 说明 |
|---|---|---|
| melee_phys | 6001 撕裂 | 近战物理 |
| melee_magic / ranged_magic | 6003 妖术弹 | 魔法（远近同一套，差别在 `attack_range`） |
| ranged_phys | 6002（预留，MVP 无此类怪，**故未建行**） | 出现时再补 |
| mixed | 6001 + 6003 并列 | 远近混打，交替出手 |

> **程序断言**：`skill_ids` 第一条必须与 `attack_type` 匹配（校验脚本 `verify_v18.py` 每次改表都跑）。`attack_type` 从此**只作人读分类与美术参考**，不再驱动行为。

## A.6 程序实现口径

```
船员出手（单队列）：
  计时到点（武器释放间隔）→ 主动CD好？ → 执行主动，CD = 武器间隔 × 主动.cd_ratio : 执行平A
  最终伤害 = 武器面板强度 × skill.power_ratio × 词缀/被动乘区 × 目标衰减
  伤害走哪个属性、武器面板强度怎么算 → 武器表决定（近战=力量，枪械=技巧+智力，法器=智力，圣典=精神）

房间出手：
  每房间独立 atk_cd 计时 → 遍历 skill_ids：
    skill.cd_ratio=0 → 按房间 atk_cd 独立计时，CD满触发
    skill.cd_ratio>0 → CD = 房间 atk_cd × skill.cd_ratio
  最终伤害 = 房间 atk × skill.power_ratio × 岗位效率（无岗位=1.0）

buff 挂载：技能执行后遍历 buff_ids → 按 buff.trigger_cond 注册/激活/持续
```

# 附录 B 配置表设计：buff 表（`05_船员与技能.xlsx` Sheet4，v2 待确认）

> buff 表是游戏内**一切持续效果**的统一归宿：转职被动、武器主动附加效果、房间自我修复、中毒流血 DoT、恐惧 debuff、临时增益（食物/药剂/祈祷）等。

## B.1 buff 表字段

| 字段 | 类型 | 控制内容 |
|---|---|---|
| buff_id | [int] | 唯一 id。号段：1xxx=增减益（临时）/ 2xxx=DoT·HoT（持续伤害/治疗）/ 3xxx=抗性·效率修正 / 4xxx=核心被动（转职）/ 5xxx=触发类被动（on_kill回复等）/ **4200~4299=遗迹怪物被动**（减伤/闪避/反伤/SAN 侵蚀/召唤/护盾/增伤）/ **4300~4399=主线精英·Boss 被动**（v1.10 新增，4310~4321 对应技能 6141~6156）/ **4400~4499=事件赋予的临时增益**（v1.10 新增，4401 血月标记 / 4402 低语回响，特征：`trigger_cond=on_apply` + `duration=999` + **`remove_on_combat_end=1`**） |
| name | [string] | buff 名（中毒·流血/猎手直觉/自我修复/ SAN侵蚀·中…） |
| buff_scope | [enum] | crew=作用于船员 / room=作用于房间或全船 / ship=作用于船只整体 / **monster=作用于怪物**。⚠ **`target_filter` 的 all_allies / all_enemies 一律以施法者阵营为参照**——怪物施放时 `all_enemies` 就是玩家船员 |
| target_filter | [enum] | 施加对象：self=仅自身 / all_allies=所有友方 / all_enemies=所有敌方 / target=当前目标（技能命中的那个） |
| trigger_cond | [enum] | **触发时机**：on_apply=施加即刻激活（被动常用）/ on_hit=下次命中 / on_hit_being=下次被命中 / on_kill=击杀目标时 / on_cast=下次施法时 / self_turn_start=自身每次回合开始 / room_start=战斗开始时 / room_damaged=房间受损时 / manual=手动激活（预留，小游戏目前无） |
| duration | [float] | **生效时长（秒）**：0=永久（被动/核心buff，直到该船员/房间存在）；>0=计时到期后清除 |
| tick_interval | [float] | **DoT·HoT 跳动间隔秒**；无持续跳动的 buff 写 0 |
| stack_limit | [int] | 最大叠加层数；默认 1（不可叠加）；流血=3，中毒=5 |
| stack_policy | [enum] | 叠加策略：refresh=重复施加仅刷新时长 / extend=叠加层数并重置时长 / replace=覆盖取新值 / ignore=重复施加无效（被动 buff 常用 ignore） |
| effect_json | [json] | **实际效果**，支持 5 大类：<br/>① 伤害 `{"dmg_pct":0.08}` / `{"dmg_flat":20}` / **`{"dmg_maxhp_pct":0.08}`（按目标最大 HP，不吃护甲）** / **`{"true_dmg_maxhp_pct":0.05}`（同上但标为真伤，可穿透减伤）**<br/>② 治疗 `{"heal_pct":0.1}` / `{"heal_flat":30}` / **`{"heal_maxhp_pct":0.05}`**<br/>③ 属性/派生修正 `{"attr_str":10}` / `{"hp_pct":0.1}` / `{"san_resist":0.15}` / `{"room_efficiency":0.08}` / **`{"atk_pct":0.3}`** / **`{"hit_rate_pct":-0.15}`** / **`{"dodge_pct":0.2}`** / **`{"dmg_taken_ranged_pct":-0.2}`**<br/>④ 行为改变 `{"fear_dmg_reduce":0.15}` / **`{"knockback_immune":1}`** / **`{"reflect_melee_pct":0.15}`** / **`{"lifesteal_pct":0.1}`** / **`{"shield_maxhp_pct":0.25}`**<br/>⑤ 自定义触发器 `{"summon_chance":0.05}` / **`{"summon":{"monster_id":"101","count":2}}`** / **`{"san_delta":-5}`**。<br/>**加粗的都是 v1.8 为怪物侧新增的 key**，船员 buff 不受影响 |
| effect_target | [enum] | **效果作用对象**：buff_holder=buff 持有者 / skill_target=技能原本的目标（如流血 DoT 作用于被击中的敌人） |
| dispellable | [int] | [bool] 是否可被净化（圣典/忏悔室清除）：被动 buff 统一=0（不可净化）；临时增减益=1 |
| buff_tag | [enum] | 分类标签：physical=物理 / magical=魔法 / mental=精神（恐惧/狂乱）/ holy=神圣 / poison=毒 / bleed=流血 / passive=核心被动 / temp_gain=临时增益 / temp_loss=临时减益。用于抗性筛选、净化目标选择、UI 图标分组 |
| passive_level_json | [json] | **核心被动数值覆盖**（转职档位解锁核心被动时配）：`{"2":0.06,"3":0.08,"4":0.10,"5":0.12,"6":0.14}`。每次升档覆盖当前生效值 |
| remove_on_death | [int] | [bool] 持有者死亡时是否清除（被动 buff=0，否则死亡带走转职奖励；临时 buff=1） |
| remove_on_combat_end | [int] | [bool] 战斗结束是否清除（临时增益/减益=1；被动=0） |
| icon_path | [string] | UI 图标路径（如 icon/buff_bleed） |
| vfx_path | [string] | 生效特效路径（如 vfx/buff_poison） |
| desc | [string] | 备注 |

## B.2 buff 字段遗漏自查（程序实际使用中常见漏项）

| 漏项 | 本字段覆盖 | 场景 |
|---|---|---|
| buff 能不能叠加 | stack_limit + stack_policy | 流血 DoT 可叠 3 层，效率 buff 只刷新不叠加 |
| 能不能被净化 | dispellable | 圣典只能清除 dispellable=1 的精神/毒 buff，核心被动不被净化 |
| 毒/流血 DoT 多久跳一次 | tick_interval | 毒每 3s 跳、流血每 2s 跳，程序按 tick_interval 计时 |
| buff 分类（用于抗性减算） | buff_tag | 物理减伤挡 physical buff、魔抗挡 magical buff、SAN 抵抗挡 mental buff |
| 被动 buff 死亡带走否 | remove_on_death | 转职被动=0（不带走）；临时中毒=1（死亡即清除） |
| buff 到期时机 | duration | 被动=0（永久）；药剂效果=300 |
| buff 作用自己还是技能目标 | effect_target | 击杀回血作用于 buff_holder（击杀者）；流血 DoT 作用于 skill_target（被打的敌人） |
| 被动 buff 触发时机不是统一 on_apply | trigger_cond | "击杀回血3%"配 on_kill，"濒死无敌"配 on_hit_being；核心被动 on_apply |
| 核心被动数值随档位升级 | passive_level_json | 转职 2→7 档覆盖更新，不是叠加 |
| UI 图标/特效 | icon_path / vfx_path | 每个 buff 独立配；美术改风格时不影响表结构 |

## B.4 程序实现口径

```
buff 生命周期：
  on_apply → 检查 dispellable/buff_tag → 注册到目标 buff 列表
  trigger_cond=on_apply → 立即执行 effect
  trigger_cond=on_hit/on_kill/... → 注册事件监听，匹配时执行 effect
  tick_interval>0 → 每 tick 执行一次 effect（DoT/HoT）
  duration>0 → 到期触发 remove；duration=0 → 直到持有者死亡/战斗结束

buff 叠加：
  stack_limit=1 → ignore 重复施加
  stack_limit>1 → 按 stack_policy：refresh 刷时长、extend 叠层、replace 覆盖
  每次叠加重新检查 effect 是否需要按层数放大（由程序硬编码，表不存）

核心被动升级：
  转职升档时，读取 passive_level_json[新档位] → 覆盖旧 effect_json 中的数值字段
```

## 程序接入说明（v1.25：`05_船员与技能.xlsx`——技能侧）

2 sheet：技能表 → buff表。

- **技能表**：`power_ratio` 伤害倍率（**炮台 atk 列已是最终值，炮台技能 power_ratio 恒 1.0，勿再乘**）；`cd_ratio` 冷却；`target_shape`+`target_max`+`falloff_json`（AOE 衰减）定范围；`trigger_cond`/`trigger_param` 条件触发；`summon_id`+`summon_count` 召唤物

- 校验：`verify_skill.py`（技能→buff 引用闭环）
