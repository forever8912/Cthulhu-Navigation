> 版本：v1.5（2026-10-28，**海面奇遇 5 个战斗组落表（只用海域1 的 4 只怪）；主线 8 只精英/Boss 补齐专属主动+被动，零新增帧**）
> 用途：**美术/AI 生图的唯一输入**（设计确认稿已通过，四张表已于 v1.1 落盘，见 §七）。

## 〇、先纠一个数

《怪物系统》标题写「**怪物名录（38 只）**」，实际表里是 **40 只**（海域1 5 / 海域2 6 / 海域3 6 / 海域4 7 / 海域5 7 / 海域6 9；普通 19 / 精英 12 / Boss 9）。本轮已把标题改为 40。**38 这个数被 00 与 01 引用过的话要一起改**——本轮未在别处引用，只改标题。

## 一、六条设计口径（改之前先看）

| # | 口径 | 理由 |
|---|---|---|
| 1 | **MVP 只做海域 1~3**，怪也只做这三片海 + 遗迹 7 主题 | 一周内容量 = 章节 1000/3000/5000 里，正好 3 片海。多做一片就多 5~9 只美术，收益为零 |
| 2 | **变体 = 0 新美术**。同模型换调色板 + 换规格系数，界面靠"名字后缀"区分 | 长章节 18 个里程碑要塞 12 场精英战，不做变体就得画 12 只。这是《03》§7.1 已定的方案 |
| 3 | **一只怪最多 1 条特性**，且必须一句话说完、玩家能看出怎么应对 | 塔防同屏 8 只，玩家看的是血条不是技能描述。两条特性等于没有特性 |
| 4 | **数值一律查表，不手调**。改 `1.75/1.30` 就整表重算（《怪物系统》§7.2） | 手调一只怪会在下一个海域被放大 1.75 倍，调参立刻失效 |
| 5 | **美术只做 5 个动作**：idle / move / atk / hit / die。不做技能独立动作，技能用 atk 帧 + 特效层叠 | 5 个状态是 1,030 帧；加一套技能动作就是 +20%，而技能差异玩家几乎看不出来 |
| 6 | **图鉴不做独立卡面**，用战斗 sprite ×2 放大 + 剪影 | 46 张卡面 = 46 张插画，成本比全部 sprite 还高，收益只有"看一眼" |

>
> **反过来说：如果哪天真要给技能做独立动作，先看 §4.11 的 72 人日**——每只 +1 个动作 ≈ +20% 帧数，8 只就是 +2.5 人日起步，而玩家在 3v3 里几乎看不出区别。

## 四、怪物美术需求（核心章节）

### 4.1 统一规格（先定这个，再画任何一张）

| 项 | 规定 |
|---|---|
| **设计尺寸** | 普通 32×32 / 精英 48×48 / 小Boss 72×72 / 主线Boss 96×96 / 遗迹Boss 80×80 |
| **实际出图尺寸** | **设计尺寸 ×2**（64 / 96 / 144 / 192 / 160）。游戏内按 50% 显示 → 高分屏不糊，AI 出图也明显更稳 |
| **朝向** | 一律**面朝右**（`+x`）。向左由程序 `scaleX = −1` 翻转，**不做镜像素材** |
| **锚点** | 脚底中心（`x = 宽/2, y = 高−1`）。海中怪锚在"水面接触点"，允许画布下沿留空 |
| **画布留白** | 四周各留 2px（设计尺寸），供受击抖动、Aura 溢出 |
| **背景** | 全透明 PNG，**禁带底色、禁带阴影烘焙**（阴影由程序画椭圆） |
| **光源** | 统一来自**上方偏左 45°**。这是全套一致性最重要的一条，破了就会"每只怪像来自不同游戏" |
| **线宽** | 1px 深色描边（`#0B0E14`），**允许断线**（断线是像素画的呼吸感，闭合描边会显呆） |

### 4.4 资源命名（与 `怪物表` 的 `art_*` 字段一一对应）


| 规则 | 说明 |
|---|---|
| `art_key` 用小写蛇形英文 | 不用中文、不用 id（id 是 101 这种数字，美术看不懂语义） |

## 五、AI 生成工作流（可直接执行）

### 5.1 提示词模板

```
[尺寸] + [风格前缀] + [该怪英文关键词串] + [动作/状态] + [环境后缀]

尺寸：普通 "32x32 pixel art sprite" / 精英 "48x48" / 小Boss "72x72" / Boss "96x96"
      （实际请求时写 2 倍：64x64 / 96x96 / 144x144 / 192x192）
风格前缀：pixel art game sprite, Lovecraftian cosmic horror, 2D side-view tower defense asset,
          facing right, single creature centered, limited 16-color palette, dark desaturated,
          light from upper-left, 1px dark outline, transparent background
环境后缀：deep ocean / dark abyss / stormy sea / misty water / void（按所属海域取一）
```

**完整示例（可直接粘贴）**

```
192x192 pixel art game sprite, Lovecraftian cosmic horror, 2D side-view tower defense asset,
facing right, single creature centered, limited 16-color palette, dark desaturated,
light from upper-left, 1px dark outline, transparent background,
burning sun disc, spokes made of reaching arms, closed eye at the center, heat haze around edge,
idle pose, menacing, stormy sea background
```

### 5.2 生成顺序（**先跑通 1 只，再批量**）

| 步 | 做什么 | 验收点 |
|---|---|---|
| 1 | 先出 **102 腐化螃蟹**（结构最简单、色块最明确） | 缩到 32px 还能认出是螃蟹 → 说明模板可用 |
| 2 | 用 102 反推"风格母版"：把它的调色板、描边、光照写成一段固定前缀 | 后续所有怪共用这段前缀 |
| 3 | 再出 **105 迷雾守望者**（Boss，信息量最大） | 96px 下轮廓仍然干净 → 说明尺寸规格没问题 |
| 4 | 出完海域1 五只，**同屏摆一起看** | 5 只放一起不"打架"（色彩、线宽、比例一致）→ 锁定母版 |
| 5 | 批量出剩余 41 只 | 每批 5~8 只，出完就同屏比对 |

> **不要一上来批量出 46 只。** 前三只决定风格母版；母版错了，46 只全部要重来。这是 AI 生图最容易踩的坑。

### 5.3 AI 生成的具体限制（写清楚，省得反复试）

| 问题 | 处理 |
|---|---|
| **AI 不做动画** | 只生成"关键姿势单帧"。5 个状态各出 1 张 → 手动补间。**别指望 AI 出 spritesheet** |
| 出图带背景 | 提示词写 `transparent background` 后仍有残留 → 用纯色底（`#FF00FF`）出图再一键抠 |
| 多出肢体 | 触手/多臂怪（309、`E-L-SCRIBE`、`E-C-BELL`）AI 容易画成 6 条或 12 条 → **在关键词里写死数量**（`exactly four tentacles`） |
| 颜色超板 | AI 会自带高饱和色 → 出图后**强制索引到 16 色板**（Aseprite: Sprite → Color Mode → Indexed，载入调色板） |
| 尺寸不准 | 一律请求 2 倍尺寸再降采样，**不要请求 32px**（AI 在极小尺寸下会崩结构） |
| 一致性 | 同一只怪的 5 个状态用 **img2img + 同一参考图**，denoise 0.55~0.65；纯 text2img 每张都会长得不一样 |

### 5.4 美术验收 checklist（每只必过）

| # | 检查项 | 不通过怎么办 |
|---|---|---|
| 1 | 缩到设计尺寸（32/48/72/96）仍能一眼认出是什么 | 加剪影特征（角、轮廓突起），不是加细节 |
| 2 | 只用 4~6 个调色板色 + ≤1 发光色 | 索引到 16 色板重导 |
| 3 | 光源在上方偏左，全图一致 | 重画高光位置 |
| 4 | 1px 深色描边，允许断线，无闭合呆板感 | 手动断开转折处的描边 |
| 5 | 无高饱和色（S ≤ 70%）、无血腥内脏、无写实人脸 | 降低饱和 / 改为剪影暗示 |
| 6 | 与同批其他怪同屏不"串色"（色相错开） | 调换主色档位 |
| 7 | 锚点在脚底中心，画布四周留 2px | 重新对齐导出 |
| 8 | 面朝右 | 水平翻转后重导 |

## 六、"塔防字段"到底缺什么（本轮已落表，含逐字段释义）

先把话说清：**上一版说"`怪物表` 缺塔防字段"是过度设计。** 复查 19 列后，现有表里已经有 8 个跟塔防直接相关的字段（`can_climb` / `can_fly` / `body_size` / `fear_value` / `attack_range` / `attack_target` / `attack_type` / `attack_interval_base`）。真正要动的只有 3 处，且**没有一处是新增列**：

| # | 改动 | 怎么做 | 为什么不需要新列 |
|---|---|---|---|
| 1 | **`attack` 单列**（你的裁定） | 一列存"对主要目标的伤害"：`attack_target` 是打人的存攻·船员，是打房/打船的存攻·房间。建筑伤害 = `attack × 档位系数` | 4 个系数进《09》全局参数表（普通 0.83 / 精英 0.34 / 小Boss 0.34 / Boss 0.50），**不是每只怪一列**。验算：12×0.83=10、11×0.83=9、35×0.34=12、59×0.34=20、40×0.50=20 —— 与 v3.1 的「攻·船员 / 攻·建筑」两列误差 ≤1 |
| 2 | 重定义 `move_speed_base` | 只表达**同屏相对快慢**（谁先贴到舷边），不参与数值 | 绝对接近时间由海域参数表给（海中 10~14s / 登船 7~11s / Boss 14~16s），是**海域级常量**，不是怪物属性。放进怪物表会让 48 行填 48 个一样的数 |
| 3 | `category` 加 `miniboss` | 枚举补一个值 | 3 只小Boss 的公式（基础精英档 ×2.2）与掉落（紫装保底）都跟精英不同，混在 `elite` 里程序没法区分 |

**明确不加的 4 个**（上一版提过，这轮撤掉）：

| 字段 | 为什么不加 |
|---|---|
| `body_type`(sea/climb/fly) | 已被 `can_climb` + `can_fly` 两个布尔完全表达。再加一个三值枚举 = 同一件事两处维护，必然不同步 |
| `approach_time` | 海域级常量（见上）。真要按怪区分的只有"飞行怪无视攀爬"，那是 `can_fly=1` |
| `climb_time` | 全局 2.4s，一个参数，不是 48 个 |
| `variant_of` / `tint_key` | `art_idle` 等 5 个路径已经能表达变体（208 指向 `monster/queen_armored/*`，就是"换色后的一张图"）。再加一列等于把美术资源关系写两遍 |
| `size_px` | 纯美术规格，在本文档 §4.1，程序不需要 |

**逐字段释义（`怪物表` 19 列，塔防口径下的实际用途）**

| 列 | 含义 | 塔防里怎么用 |
|---|---|---|
| `monster_id` | 怪物唯一 id | 101~312 主线、701~763 遗迹，两段不重叠 |
| `name` | 显示名 | 战斗飘字 / 图鉴 |
| `category` | normal / elite / miniboss / boss | 决定**事件结算组的档位**（掉落已改为按事件结算，见 §七末）、决定"能不能被拖拽锁定"、决定是否进精英战里程碑 |
| `tags` | 标签集（竖线分隔） | `undead` 吃圣典额外伤害；`flying` 无视攀爬；`aquatic` 只能在水中移动；`island_*` 是遗迹主题标签（决定 island 表抽哪只） |
| `art_idle/move/attack/hit/die` | 5 个动作资源路径 | 直接对应 anim 状态机。**变体靠路径区分，不靠字段** |
| `move_speed_base` | 相对速度（1.0=人类） | **只做同屏排序**：决定 4 只怪里谁先贴舷，进而决定玩家的集火顺序。不乘任何数值 |
| `attack_interval_base` | 出手间隔（秒） | 塔防里真正的压力来源。同 DPS 下"快而轻"比"慢而重"更危险（打断治疗、抢修窗口更短） |
| `attack_type` | 物理/魔法/混合 | 决定吃护甲还是吃魔抗，是玩家换装的依据 |
| `attack_target` | nearest / lowest_hp / ship / room | **塔防分线的核心**：`room` 走"拆房线"、`lowest_hp` 走"点杀线"、`ship` 是 Boss 专线。**建筑压力就靠这个字段 + 高 attack，不需要第二列攻击值** |
| `attack_range` | 攻击距离（像素） | 海中怪要贴到舷边才打房，`60~80` 表示"必须靠上来"；`250~400` 是远程/触手，能在射程外先手 |
| `can_climb` | 能否攀爬上舷 | 0 = 海中怪，全程在射程内挨打（所以它游得慢，§1.4 的补偿）；1 = 会爬上甲板 |
| `can_fly` | 是否走空中路径 | 1 = 跳过攀爬 2.4s，玩家的"海面窗口"对它是无效的，只能用远程提前打 |
| `body_size` | small/medium/large/huge | 决定受击框与同屏占位，也决定它会不会挡住后面的怪（塔防的"肉盾挡枪"） |
| `fear_value` | 首次出现的 SAN 伤害 | 恐惧不是战斗数值，是资源压力：一屏 8 只普通怪 = 80 点 SAN，等于半管 |
| `sfx_id` | 音效 id | 空 = 用 `category` 的默认组（§4.10 按类型复用） |
| `desc` | 策划备注 | 一句话特性 + 美术提示，**不参与任何计算** |

> **一句话总结**：这张表不缺"塔防字段"，缺的是**"attack 这一列到底指什么"的定义**。定义清楚（对主要目标的伤害 + 4 个档位系数换算建筑伤害），19 列就够用。

**v1.2 口径变更：掉落从「按只」改「按事件」**

原方案把 `drop_group_id` 挂在 `怪物等级表`，48 只怪各配一个组——这带来两个问题：①Boss 战一场 13 只怪要结算 13 次，程序里是 13 次独立随机，方差大且难做结算界面；②同等级小怪（1001/1002/1003 都是 L1 普通）挂 3 个不同组，纯属重复配置。

改为：**一个事件 = 一个结算组**，全部波次清空后统一结算 1 次。

| 改了 | 原来 | 现在 |
|---|---|---|
| 引用位置 | ~~`怪物等级表.drop_group_id`~~（v1.2 已删列） | `怪物组表.clear_drop_group_id`（42 行） |
| 组数 | 每组怪一个档位组，20 事件 → 48 个引用点 | **20 事件 → 11 个结算组**，同档同类共用 |
| 结算次数 | 8 只怪 = 8 次 | **1 次**（`roll_times` 把随机次数折叠进条目） |
| 币区间 | 单只 ±20% | 事件 ±11%（汇总后方差收敛） |
| 币期望 | 每只 22.5 / 37.5 / 57.5 | **不变**，= 事件只数 × 锚点（校验偏差 0.0%） |

**顺带修掉一个配置漏洞**：原 4003 / 4008 / 4103 是 `mode=all` 却挂着 2 条 weight 条目（图纸二选一）。按 `all` 的语义「逐条执行」，这 2 条会**各掉 1 张图纸**，而不是二选一。现已把这三个组改为 `pick_n, pick=1`，并在表头把 `mode` 语义定死：**`all` 禁止出现 weight，weight 只能配 `pick_n`**。

`4001~4003` 的旧币量（50~150 / 150~300 / 800~1200）比《02》§6.1 的「普通 22.5 / 精英 90 / Boss 300」高约 4 倍，该问题在 v1.1 已按《02》重写；遗迹 3 组（4016~4018）**只出材料、不出币**，尊重 #35.6「遗迹赚东西不赚币」。遗迹的**事件总结算**另一层，走 `4201~4299`，在 `island_settle` 表里配。
