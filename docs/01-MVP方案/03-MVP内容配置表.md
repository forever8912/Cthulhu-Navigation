```
海图遇到遗迹岛（上岛前就能看到主题名，玩家决定要不要去）
        │
        ▼
   编队 3 人（少 1 人不能进）
        │  消耗：食物 12
        ▼
┌─────────────────────────────────────────────┐
│ 进度 0% ──────────────────────────► 100%   │
│                                             │
│  N1 外围   [选项 A / 选项 B / 撤退]  +20%  │
│  N2 浅层   [选项 A / 选项 B / 撤退]  +20%  │  ← 可能有战斗
│  N3 中层   [选项 A / 选项 B / 撤退]  +20%  │  ← 可能有战斗
│  N4 深处   [选项 A / 选项 B / 撤退]  +20%  │  ← 休整点
│  N5 核心   [选项 A / 选项 B]         +20%  │  ← 不可撤退，必战
└─────────────────────────────────────────────┘
        │
        ├─ 进度 100% → 通关结算（币 + 材料 + 首通强化石）
        ├─ 点了「撤退」→ 立即结束，**已拾取 100% 保留**，无结算奖励
        └─ 战斗判负（全灭/超时）→ **表现为"被拖回船上撤退"**，角色不死，
                                已拾取**按数量遗失 30%**（硬战利品不遗失），然后结算
```

**判负不是"死"，是"撤"。** 三个人被打倒，同伴把他们拖回船上——**这是撤退的另一种触发方式，不是游戏结束**。所以：
- **角色不死**，回船后 HP 恢复至 50%，不进伤病，不掉特性（《03》§3.3.1「死亡」行）；
- **硬战利品（装备/图纸/强化石/技能书/橙装碎片）一律保留**——它们是"塞在怀里带出来的"，丢了会让玩家觉得白干；
- **普通材料与贝壳币按 30% 遗失**（`lose_penalty=0.30`，向下取整，单类最多扣到剩 1）——这是"散了一地，只来得及捡回大半"。

**结算界面必须按这个顺序演**（顺序错了玩家会以为东西被吞了）：

```
┌──────────────────────────────┐
│  探索失败 · 已撤离            │
│  遗失了部分物资               │
│   木材 −28   铁 −9   币 −54  │
├──────────────────────────────┤
│  带回：                       │
│   ✔ 完美装备 ×1   ✔ 强化石 ×2 │
│   木材 ×62   铁 ×21  币 ×126  │
└──────────────────────────────┘
```
先报"丢了什么"，再报"带回了什么"。**反过来演（先给后扣）会被当成系统吞奖励**，这是必须写进 UI 规格的一条。

**主动撤退 vs 判负的差别**：主动撤退 **0 遗失**（我自己走出来的，东西都在手上）；判负 **30% 遗失**（被打出来的，散了一地）。**这个差别是"撤退"这个选项唯一的价值来源**——如果撤退也扣，玩家就永远不会撤，5 步结构会退化成"一路点到底"。

#### 3.3.1 规则总表

| 项 | 规则 | 为什么 |
|---|---|---|
| 编队 | **固定 3 人**（不足 3 人不能进）。开局就有 3 名甲板战斗员，第 1 章第一次遇到遗迹就能进 | 3 人是"能打能扛能奶"的最小完整编队；人多了就变成"全船都上"，跟甲板战没区别 |
| 战斗 | **3v3 自动战斗**（与竞技场同一套结算），玩家可切技能、可点"收兵" | 复用一套战斗，省一份开发；也保证"我竞技场打得过，遗迹就打不过"这种错觉不出现 |
| **战斗中「收兵」** | **按判负处理**（30% 遗失），**不等于节点界面的「撤退」** | **这是必须堵的漏洞**：允许"快输了就收兵"等于把判负的代价变成 0，30% 遗失永远不会发生，N5 必战也就没有压力了。**想零遗失，只能在进战斗之前点「撤退」** |
| 进度 | 0~100，**每节点 +20**。战斗节点必须**打赢**才 +20 | 进度是"确定性"，玩家随时知道"我还差几步"——比"随机触发"少一半焦虑 |
| 撤退 | **N1~N4 常驻第三选项**，免费，保留已得 | 每层都要让玩家回答"还往下吗"，这才是探索 |
| 核心 | **N5 不可撤退**，且**必有一战** | 走到最后一步不能"看一眼就跑"，否则核心永远只是免费抽奖 |
| 死亡 | **遗迹内不死亡**。HP 归零 = 倒地 → 判负 | 3 人小队死一个就是灾难；"不死亡"让玩家敢带主力来 |
| **判负** | 全灭或 45s 超时 → **按"撤退"表现收场**：角色被拖回船、**不死不伤**、回船 HP 50%；已拾取**普通材料与币遗失 30%**，**装备/图纸/强化石/技能书/橙装碎片 0 遗失** | 判负必须有代价（否则 N5 必战没有压力），但代价只能是"少赚一部分"，不能是"人没了"或"东西全没" |
| **结算界面** | 失败时：**先演"遗失了什么"，再演"带回了什么"**（见 §3.3.0 的界面示意） | 先给后扣会被玩家当成系统吞奖励；先扣后给才读得出"我被打出来了，但还带回了不少" |
| HP 恢复 | 每完成 1 个节点回 **8%**；N4 的"休整"选项额外回 15% | 不给恢复，第 4 步就必灭；给太多，核心战没有压力 |
| 耗时 | 节点基础 12~25s + 战斗 9~31s，**100% 通关约 2~2.5 分钟** | 与《02》§"一次探索 2.5 分钟"口径一致 |
| 消耗 | **食物 12**（3 人往返） | 不耗弹药——在陆上，火枪用随身弹药，记在"探索消耗"里更简单 |
| 判定 | **确定性阈值**：`阈值 = 6 + 2×(海域−1)`，`判定值 = 队伍中最高相关属性 + 装备加成` | **不做概率判定**。确定性判定让"换个技巧高的人来"成为解法，符合"养成兑现"；概率判定只会让玩家觉得被系统耍 |
| 通关后 | 同一主题再次遇到，可选**快速重探**：按上次路线 60% 结算，**无战斗、无独占掉落** | 独占产出（图纸/紫装）不能靠扫荡拿，否则"探索"就没意义了 |
| 重复 | 遗迹岛 24% 权重（一周约 25 次，摊到 7 主题 ≈ 每主题 3.6 次） | 见《02》§五 |

#### 3.3.2 配表结构（v1.9：并入 `01_海域与关卡.xlsx` 的事件三表，`10` 号表已废弃）

> **v1.9 的口径变更：遗迹探索不是独立系统，它就是「事件」的一种（`type=island`）。** 原来给它单开一个 `10_岛屿与遗迹.xlsx`，结果同一件事在两张表里各有一套定义——`01` 的事件池指向 `10` 的 island_id，`10` 的选项又要回头引用 `01` 的怪物组和《03》的掉落组。**现在全部并回事件体系，`10` 号表删除。**
>
> 判断依据很简单：一座岛的探索流程，拆到最底层只有四件事——
> ① 一个事件（有名字、有图标、有一句氛围文案）；
> ② 若干站（节点，每站推 20% 进度）；
> ③ 每站给玩家 2 个按钮（选项，带判定条件，成功/失败各导一个结果组）；
> ④ 结果组（给材料 / 扣 SAN / 开打 / 推进度 / 结束）。
> **这四件事，海面奇遇也一样需要**（三选一、判定、给东西）。所以它们本来就该是同一组表，而不是两套。

**七张表的去向**

| 原 `10` 的表 | 行数 | 去向 | 说明 |
|---|---|---|---|
| `island` | 7 | → `01/事件表`（**event_id 直接用 W01 / T01 … R01**，`type=island`） | 加 `theme` / `node_count` / `settle_drop_group_id` / `first_clear_group_id` 四列 |
| `island_node` | 35 | → `01/事件节点表`（新建） | 每岛 5 站，`seq` 1~5 |
| `island_option` | 70 | → `01/事件选项表`（**与海面奇遇共用一张表**） | 加 `node_id` / `check` / `result_fail` 三列 |
| `island_result` | 279 | → `01/事件结果表`（新建） | 11 种 type 一个不少 |
| `island_wave` | 30（22 组） | → `02/怪物组表` + `02/怪物组波次表` | 号段 **7001~7063**，按主题分段 |
| `island_enemy` | 22 | → **删除** | 22 只遗迹怪**早就在 `02/怪物表` 里**（701~763），原表只是同一批怪的 HP/攻击副本，属于纯重复 |
| `island_settle` | 8 | → `01/事件表` 的 `settle_drop_group_id` / `first_clear_group_id` | 结算本来就是"给一个掉落组"，不需要第三张表 |

**四张表的字段**

| # | 表 | 主键 | 关键字段 | 职责 |
|---|---|---|---|---|
| 1 | `事件表` | `event_id` | `type`（island=探索）/ `theme` / `node_count` / `settle_drop_group_id` / `first_clear_group_id` | 事件头信息。**island 的 event_id 就是 island_id**，不再有第二套 id |
| 2 | `事件节点表` | `node_id` | `event_id` / `seq` / `layer` / `scene` / `base_time` / `progress_add` / `can_retreat` | 一站。5 站 × 20% = 100%，第 5 站不可撤 |
| 3 | `事件选项表` | `option_id` | `event_id` / `node_id` / `sort_order` / `option_text` / `desc`（玩家可见提示）/ `check` / `result_type=result_group` / `result_id` / `result_fail` | 两个按钮。`check` 空=必成，非空=确定性判定（不掷骰） |
| 4 | `事件结果表` | `group_id` + `seq` | `type` / `params` / `float_text` | **原子结果**，一个组多行按 `seq` 依次执行 |

> **原来 7 张表里那些"每岛填同一个值"的列，全部提为全局参数**（`09_全局参数.xlsx`）：`island_node_count=5` / `island_squad_size=3` / `island_cost_food=12` / `island_rerun_scan_ratio=0.6` / `island_lose_penalty=0.30` / `island_lose_protect`。7 座岛这几项一个不差，没有按岛差异化的理由——**列在表里等于给了 7 次填错的机会**。真要出现 4 站或 6 站的岛，用事件表的 `node_count` 覆盖。
>
> **战斗波次也一样。** 岛屿的 22 场遭遇战并入 `怪物组表` 后，和其他 20 个战斗事件走完全相同的字段：`clear_drop_group_id` 就是本场掉落（杂兵 4016 / 精英 4017 / 核心 4018），多波次的事只在 `怪物组波次表` 里。副官的 `hp_scale=dmg_scale=0.5` 是波次表新增的两列——**只缩血不缩伤会让核心波掉血率从 54% 冲到 78%**，这条硬规则现在有字段承载了。

> **已落盘（v1.10）**：`01_海域与关卡.xlsx` 共 11 张表，其中 `事件表` **33 行**（6 条海面事件 + 7 座岛 + **20 条海面奇遇**）/ `事件节点表` 35 行 / `事件选项表` **130 行**（70 island + **60 choice**）/ `事件结果表` **391 行（182 个结果组）**；`02` 的 `怪物组表` **47 行**、`怪物组波次表` **108 行**。
>
> **`type` 现在有 3 种在跑**：`battle`（6 条，战斗事件，无选项）、`shop`（1 条）、`island`（7 座，走 事件节点表 的 5 站）、**`choice`（20 条，海面奇遇，"一次性多选一、不进节点"）**。判断一个事件走不走 `事件节点表`，只看 `node_count`：**island 填 5，choice 填 0**——所以 choice 的选项 `node_id` 全部为空，这是结构上的约定，不是偷懒。

**`island_result.type` 的取值（v1.7 定稿 11 种；`equip` / `trait` 是落表时新增的）**

| type | params 格式（落盘实际写法） | 说明 |
|---|---|---|
| `item` | `item=itm_wood;qty=25` | 给材料/图纸。**`qty` 允许为负**（`qty=-20` = 扣除，用于 A01-N2-A 投 20 份食物） |
| `shell` | `shell=150` | 给贝壳币 |
| `san` | `san=-10;scope=all` | SAN 增减（`scope=all` 全队 / `one` 随机 1 人） |
| `hp` | `hp=-0.08;scope=all` | HP 百分比增减（**小数**，不是 8） |
| **`equip`** | `pool=2;qty=1` | 给装备实例（`pool` 引用《03》装备掉落权重表 `equip_drop_id`）。**v1.7 新增**：装备是带品质/词缀的实例化对象，没有固定 `item_id`，混进 `item` 会逼程序解析字符串前缀 |
| `battle` | `group=7001;on_win=RS-W3B-WIN;on_lose=RS-LOSE` | 引入战斗（`group` 引用 `02` 怪物组，**岛屿用 7001~7063**），胜利跳结果组。**`on_lose` 必须显式写 `RS-LOSE`**——v1.9 改：原来规定「省略、程序写死」，但落表时 28 条全被省略，断言「任何 battle 的 on_lose 不为空」就永远落空。现在一律显式填，校验脚本强制 |
| `progress` | `progress=20` | 推进度（**只在"这件事做成了"时给**） |
| `buff` | `buff=4401` | **引用《05》buff 表的 id**，不写内联数值。**v1.10 首次使用（4 处）**：S01/S05「血月标记」→ `4401`、S02「低语回响」→ `4402`。被引用的 buff 必须是 `trigger_cond=on_apply` + `remove_on_combat_end=1`，否则会永久挂在船员身上——校验脚本强制。原 v1.7 写的 `buff=rampage;value=1.15;turns=3` 是内联格式，落表时没有 buff_id 可查，已废弃 |
| **`trait`** | `trait=2015;scope=all` | 施加船员特性。**v1.7 新增**：A01-N5-A 的「契约印记」是永久不可清除特性，用 `buff` 表达不了永久性 |
| `end` | `reason=retreat` / `reason=lose;loss=0.30` | 立即结束探索并结算（`lose` 走 30% 遗失判定） |
| `roll` | `chance=0.5;hit=RS-R5A-GOOD;miss=RS-R5A-BAD` | **概率分支**。`chance` = 命中概率，`hit`/`miss` 各跳一个结果组；**`miss=empty` 表示"什么都没发生"**（T01/L01 的「50% 扣 SAN」用这个写法，不需要造一个空组）。两种用法：R01 的 50/50 二选一（`hit`/`miss` 都给实组）、T01/L01 的 50% 追加惩罚（`miss=empty`） |

> **`battle` 和 `roll` 是仅有的两种跳转型 type**。`battle` 的 `on_win` / `on_lose` **都必填**，`on_lose` 一律 `RS-LOSE`；`roll` 的 `chance` 必须在 (0,1) 开区间内。**这两条已用校验脚本强制断言**——70 条选项里任何一条违反，脚本直接报错。**v1.9 修掉的真 bug**：原 28 条 `battle` 全都没写 `on_lose`，按旧文档「程序写死」的说法能跑，但配表一旦有别的败北分支就分不清了。现已全部补齐。

> **为什么必须有 `roll`**：核心抉择里有一类"赌"（直视神像 / 读最后三页 / 直视眼睛），是 50% 大奖 / 50% 重罚。用 `item` 带 `rate` 表达不了"二选一"，用 `battle` 又变成"打不打得过"而不是"敢不敢"。`roll` 是唯一干净的写法。**v1.7 落表时实际有 3 处在用**：R01-N5-A（真二选一，`hit`/`miss` 都给实组）、T01-N5-A 与 L01-N5-A（50% 追加惩罚，`miss=empty`）。

> **`equip` 背后的 `03/装备掉落权重表` 长什么样（v1.10 修了一个真洞）**
>
> 这张表是**二维权重网格**：行 = (`quality_id`, `slot`)，值 = 权重；程序先按权重抽中一行，再去 `06/装备阶段表` 里找"该品质 + 该槽 + `tier_range` 覆盖当前海域"的装备实例。
>
> **装备槽位只有 4 个：`weapon` 武器 / `armor` 护甲 / `trinket` 饰品 / `relic` 奇物。没有"副手"**——本作不做双持、不做盾牌，双手武器是唯一形态。`relic`（v1.11 由 `tool` 更名）不是副手，是**奇物位**：既装工具（`4001` 铁扳手 / `4002` 鱼竿，生活向加成），也装遗物（`4003` 异教面具 / `4004` 圣髑匣，SAN 向）。**槽位语义从"我带了什么工具"变成"我信什么东西"**，往后所有"来历不明但有用的东西"都有地方放，不用每次加内容就动槽位。
>
> **修掉的洞**：v1.9 及之前，两个权重组（`1` = tier 1~3、`2` = tier 4~7）**只配了 `weapon` 一种 slot**。结果是"打怪只掉武器，护甲/饰品/奇物永远掉不出来，只能靠工坊锻造"——而锻造要材料、要工坊等级，中期玩家会出现"全身只有武器在换"的空档。v1.10 补齐三槽，9 行 → **36 行**：
>
> | 权重组 | 槽位系数 | 武器占比 | 品质曲线（q1→q7） |
> |---|---|---|---|
> | `1`（tier 1~3） | 武器 1.0 / 护甲 0.5 / 饰品 0.35 / 奇物 0.25 | **47.9%** | 50.3 / 31.1 / 15.6 / 3.0%（**与补槽前逐档一致**） |
> | `2`（tier 4~7） | 同上 | **47.4%** | 19.9 / 35.1 / 29.9 / 11.8 / 3.3%（**与补槽前逐档一致**） |
>
> 补槽的原则是**只改槽位分布、不动品质曲线**——原 weapon-only 的每一档品质占比原样保留，所以"一周能出几件紫装"这个经济账一个字都不用重算。
>
> **还剩一个未修的口子（已知，需要拍板）**：`06/装备线表` 的 13 条线是 **武器 7 条（7 系各 1）+ 护甲 2 条（海洋/战争）+ 饰品 2 条（海洋/死亡）+ 工具 2 条（锻造/狩猎）**。如果 `class_line` 当硬门槛用，**魔法系与光明系的角色没有任何护甲/饰品/工具可穿**，等于少两个槽的词条。两种修法：① 补 5~8 条装备线（每条要 7 阶阶段行 + 核心名 + 7 阶专名，是纯内容量）；② 把非武器线的 `class_line` 改为 `none` = 7 系通用（护甲/饰品/工具都不提供 `base_power`，只提供词条，按系切分没有数值意义）。**当前配置按 ① 的现状保留**，等定。

#### 3.3.5 这套结构的设计红线（改之前先看）

| # | 红线 | 一旦破了会怎样 |
|---|---|---|
| 1 | **主动撤退 0 遗失；判负只遗失"普通材料 + 币"的 30%，硬战利品（装备/图纸/石/技能书/碎片）永不遗失** | 破"硬战利品不遗失"，玩家就不敢走 N5；破"撤退 0 遗失"，玩家就永远不撤，5 步结构退化成"一路点到底" |
| 2 | **进度只在"事情做成了"时给**（战斗必须赢） | 输也推进度 = 5 步没有意义，玩家会一路点最便宜的选项冲到结算 |
| 3 | **N5 不可撤退 + 必战** | 核心能跑，就是免费抽奖；必战才让"我血不够了要不要现在撤"变成真决策 |

| 5 | **损毁/死亡不进遗迹** | 3 人小队死一个就废了整条线；遗迹的风险应该是"少赚"，不是"人物没了" |

### 3.4 竞技场岛（v1.4 重写：10 层封顶 → **无限层**）

> **它解决一个真实需求**：玩家在长章节里会想"我现在就想打一场，但不想推进度"（因为推图会消耗资源、会掉进度）。竞技场是唯一的"纯战斗、零风险、有奖励"的地方。
>
> **v1.4 改了三件事**：① 层数 **10 → 无限**；② 频控从"每航段限进 1 次"改成 **"从历史最高层 −3 起打"**；③ 难度从"乘玩家均值"改成 **"按层数取绝对锚点"**。三条改动互为一体，缺一条就会崩（论证见 3.4.2）。

#### 3.4.1 核心规则

| 项 | 规则 |
|---|---|
| 入口 | 竞技场岛（出现权重 12，一周约 13 次） |
| 层数 | **无限，`n ≥ 1`，不设上限** |
| **历史最高层** | **到达过的最深层**（含挑战失败的那一层）。字段 `arena_max_layer`，只增不减 |
| 起点 | 每次进入从 **`max(1, 历史最高层 − 3)`** 开始 |
| 保底 | 起点起 **3 层**是"回溯层"（都已通过过），**保底结算这 3 层奖励** |
| 新层 | **历史最高层本身**（若从未通过）及更高层；首通结算 **100%** |
| 回溯层结算 | 奖励 **×40%**，**不给强化石、不给装备**（只给币 + 普通材料） |
| 上场人数 | **1~3 名**（不能全员——船还要有人开） |
| 死亡 | **不会死亡**。HP 归零 = 判负，回船后 HP 恢复至 30% |
| 单场时长 | 25~35 秒（纯战斗，不航行） |
| 消耗 | 每场 **食物 = 上场人数 × 3**；**无进入次数限制** |
| 失败 | 本次挑战立即结束，已得奖励 100% 保留，**历史最高层不变** |
| 主动退出 | 随时可退（点"收兵"），已得保留。**这是保底 3 层能成立的前提** |

> **"保底 3 层"的准确定义**：不是白送 3 层，而是**你的起点永远比你打不过的那层低 3 层**。玩家卡在第 12 层时，下次从第 9 层开打——9/10/11 是他已经赢过的，理论上必过，所以这 3 层是"确定收益"，只是打了 40% 折。**它保证"我打不过新层也不会空手走"，但不给"白拿"路径。**

#### 3.4.2 为什么"无限层 + 回溯 3 层"比"10 层封顶 + 每航段 1 次"好

旧的 10 层方案有三个问题，而且都是**会随时间放大**的：

| 旧方案的问题 | 后果 | 新方案的处置 |
|---|---|---|
| 10 层封顶 | 会玩的玩家第 2 周就打穿，之后竞技场变成"再也没东西可打" | 层数无限，天花板由玩家战力决定，永远差 1~3 层 |
| 每航段限进 1 次 | "我现在就想打"变成"我得先走到下一个航段"——**用地理位置做频控，手感很差** | 取消次数限制，改用"起点回溯"做频控 |
| 挑战失败 = 连胜归零 | 一旦卡层，每次进去都从第 1 层重打，重复劳动 | 起点 = 最高层 −3，**永远不会让你重打第 1 层** |

**那为什么不会变成"无限刷"？** 三道闸，全是软的：

1. **回溯源层 ×40% 且不给石/装备** → 单次回溯 3 层约 200~300 币，折合 80 币/分钟，**低于推图的 210 币/分钟**（《02》§6.2 口径）。刷它不如推图。
2. **每场吃食物（人数 × 3）** → 3 人队打 3 场 = 27 食物。食物是产能，不是白给。
3. **新层才是收益来源，而新层过不去就是过不去** → 想多拿，只能变强；变强要靠推图和强化，不靠竞技场。

> **一句话概括经济定位**：竞技场是**把"战力"换成"强化石"的兑换机**，不是产出机。它的币收益低于推图（所以不抢主线时间），但强化石只能在这里稳定拿（所以变强必须来这里）。

#### 3.4.3 难度曲线（无限层的真正难点）

**不能再用"玩家上场均值 × 系数"了。** 那是死锁：玩家战力涨 30%，对手同步涨 30%，比值不变——**玩家永远过不了第 n+1 层，层数进度会永久冻结在第 1 周的水平**。旧方案只做 10 层，所以这个洞没暴露；一旦改成无限层，它第一天就会爆。

**正解：对手强度锚定"层数"，不锚定"玩家"。**

```
对手属性 = 基准属性(n) × 0.85
基准属性(n) = 100 × 1.11^(n−1)      // 1 点 = 第 1 章开局标准船员（主属性 4~8）的单人四维合计
```

| 层 | 对手战力（基准 ×0.85） | 对应内容进度锚点 | 目标通过率 |
|---|---|---|---|
| 1 | **85** | 第 1 章开局 | 95% |
| 5 | **129** | 第 1 章末期 | 70% |
| 10 | **217** | 第 2 章中期 | 60% |
| 15 | **366** | 第 2 章末期 | 60% |
| 20 | **617** | 第 3 章末期 | 55% |
| 25 | **1,040** | 奇迹之海第 2 层 | 50% |
| 30 | **1,753** | 奇迹之海第 4 层 | 50% |
| 30+ | `85 × 1.11^(n−1)` | 每 5 层 ≈ 奇迹之海 1 层 | 45~55% |

- **`1.11` 这个数是怎么来的**：奇迹之海每 1,500 里一层，层 n 怪物查海域表第 n 行（沿用 `1.75^(n-1)` 外推，决策 #32）。竞技场要"跟着内容走"，就得分摊到 5 层一档——`1.75^(1/5) ≈ 1.119`，取 **1.11**。**这不是拍脑袋的数，是和主线怪物成长对齐的。**
- **通过率控制在 45~60% 是刻意的**：竞技场不该是"稳赢的地方"（那会变成按按钮领奖），也不该是"上去就死"（那没人去）。**一局能过 1~2 个新层**，正好是一次挑战的手感。
- **锚点已落表**：《11_竞技场.xlsx》层数锚点表（1~50 每 5 层一档共 11 锚点），段内线性插值。数值木桩阶段用实际队伍跑一遍第 5/10/15/20 层的通过率，偏了就调锚点、**不要调 1.11**。

#### 3.4.4 对手生成（v1.20 重写：程序假人 → **玩家镜像**）

> **v1.4 的方案是"程序按锚点公式造假人"**：属性对、手感对，但名字是编的、阵容是木桩，打十场就认出对面是 NPC。v1.20 改成**镜像制**：对手队伍来自**其他真实玩家上传的"最强 3 人"快照**——属性/外貌/名称/装备/技能全是真数据，竞技场才真的像"和其他船长打"。**锚点公式没有删**，它退到兜底位：镜像不足时虚拟船长补位仍按它生成，依然是防死锁的平衡锚。

| 参数 | 规则 |
|---|---|
| **数据源** | 每名玩家上报**最强 3 名角色**快照（名称/职业/四维/外貌/装备摘要/技能，契约见 11 表《玩家镜像契约表》）；历史最高层、阵容或装备变化时全量重传 |
| **选取窗口** | **只从"竞技场历史最高层与玩家相差 ≤3 层"的玩家镜像里选取**（`mirror_window=3`）——±3 层内的玩家战力天然贴近锚点曲线，**匹配即平衡** |
| 候选池 | 每次进入随机抽 **5 名候选船长**（`mirror_pool_size=5`），战前预览职业+主属性+装备品质后挑一个打 |
| 队伍规模 | 与玩家上场人数相同（1v1 / 2v2 / 3v3）；镜像队伍取其 chars 前 N 名（N=玩家上场人数） |
| **兜底** | 窗口内镜像不足 5 名 → **虚拟船长补位**：虚拟层在 ±3 层内均匀取、属性按该层锚点公式生成；名字从名池表（100 假船长名）取、外貌按 05 船员外貌表 roll。新玩家 / 离线模式全部走兜底 |
| 属性分配 | 镜像天然是真实玩家阵容（含偏科）；虚拟船长强制至少 1 项偏科（18 层起 2 项），模拟"偏科的老玩家"而不是均衡木桩 |
| 装备 | 同档随机，品质随层数提升（第 8 层起出现紫装，第 18 层起全紫——对手生成规则表 3 档） |
| 职业 | **不生成玩家没有的职业系**（避免信息不对称） |
| 技能 | **只使用玩家已解锁的技能**（避免"它有你没有"的挫败） |

> **隐私与展示口径**：对手列表只展示船长名（昵称脱敏 ≤8 字）与阵容，不暴露 uid/存档细节；快照只有战斗需要的字段，不含资源/船舱布局。

> **竞技场是唯一能"看到别人怎么打"的地方**：单机游戏里没有真实 PVP，但玩家需要"别人是怎么配装/配岗的"这个参照物。对手阵容可以直接当作**配装模板**给玩家看——这是它区别于推图的第二层价值。

#### 3.5.2 四条设计约束（改之前先看）

| # | 约束 | 配置上怎么保证 | 理由 |
|---|---|---|---|
| 1 | **"误判"选项必须看起来更赚**（更多材料/更快/不用绕路） | B 档的 `desc` 一律写收益、不写风险（"能装满两个舱"而非"可能引来怪"） | 如果误判选项一眼就是坑，玩家不会选，三选一形同虚设。**要骗到才有博弈** |
| 2 | **每条必须有免费"退出"，且退出不扣任何东西** | C 档 = `result_type=close` + **不建结果组**，结构上不可能扣东西 | 低挫败红线；也是"我看不懂就走"的体面出口。v1.4 原设计里 H02/H03 的"离开 SAN −5"违反本条，**v1.10 已删除** |
| 3 | **稀有材料只在"正解"产出；误判打赢只给普通材料 + 币** | `verify_sea.py` 强制断言：任何 `RS-C*-A` 之外的结果组出现 `sm_*` 即报错 | 否则玩家会故意选错去刷战斗——那海面奇遇就变成"随机刷怪点"了 |

## 四、漂流物事件池（39 主池模板 + 7 特殊，三层结构）

> **v1.1 重构**：v1.0 的"12 模板平铺"把漂流物当成了"掉资源的桶"，但**漂流物在玩家认知里是一类事件**——木箱、铁桶、水桶、落难船员、宝箱，捞起来的手感和后续动作完全不同。
> 所以改成**三层抽取**：先抽大类（决定"这是什么"）→ 再抽模板（决定"具体长什么样"）→ 再 roll 数量（决定"这次赚多少"）。同一套模板靠这三层能撑出约 120 种体感，够 600 次点击不腻。

### 4.0 三层结构（程序实现口径）

```
漂流物触发（每 50 里）
  → 第 1 层：抽大类（10 类，权重合计 100）
  → 第 2 层：类内按权重抽模板 id
  → 第 3 层：roll 数量 = 模板区间 × 海域系数 (1 + 0.35 × (海域-1))
  → 独立判定：特殊池（7 条，合计约 9.3%）
```

- **海域系数只乘数量，不乘品类**：海域 3 的一个木箱给 1.7 倍木材，但不会突然开出紫装。稀有度扩张只走"特殊池"和"宝箱类"，保证概率可读
- **同类不连出 3 次**：程序记录最近 2 次大类，同类的权重减半。这是防"今天全是海草"的体验保险，实现成本 3 行代码
- **本期不做的**：漂流物不做"是否打捞"的选择（点了就捞）。一次点击只值 2 秒，加选择会把节奏拖死。**需要选择的东西放在岛屿事件里，不放在漂流物里**

#### G 船员类（权重 4）

> **v1.3 重写：从"捞到即获得"改为"看到再决定"**。原来的问题很直接——四维 4~8 的船员对玩家几乎没有价值，捞上来就是占床位+吃口粮，玩家会本能地希望"别来"。但本作是单机、低挫败，**不该让玩家为了一个随机结果而难受**。
> 所以改成：**属性在决定之前就可见，救不救由玩家自己判断，三条路都有正收益**。

##### G.0 决策流程（程序口径）

```
漂流物触发 G 类
  → 弹出「海上遭遇」界面（游戏暂停，不打断航行计时）
  → 显示每个人的：头像 / 四维 / 特性（若有）/ 状态（健康·受伤·濒死）
  → 玩家对每个人独立三选一：
      ① 救上船     → 占 1 船员位，SAN +4
      ② 给补给     → 消耗食物 20，SAN +3，人不留
      ③ 驶离       → SAN 不变，无消耗
  → 界面关闭，继续航行
```

- **属性必须可见**。看不到属性就选，是赌博；看得到再选，是判断——玩家要的是后者
- **驶离不扣 SAN**。扣了就成了"逼你做好人"，和低挫败定位冲突
- **给补给是第三条路**：玩家不必在"养一个废人"和"见死不救"之间二选一。这是本次改动最关键的一处
- 一次遭遇最多出现 **3 人**（救生艇），逐个独立决定

##### G.1 属性分布（三档 + 明珠，合计 100%）

| 档 | 概率 | 四维 | 特性 | 状态 | 玩家会怎么选 |
|---|---|---|---|---|---|
| **拖油瓶** | **47%** | 4~8（全低） | 30% 带 1 条负面 | 15% 濒死 | 多数给补给或驶离；**缺人时仍会救**（能填岗、能挡刀） |
| **偏科** | **35%** | 一项 9~12，其余 2~5 | 20% 带 1 负面 | 15% 濒死 | 看自己缺什么——缺智力的会救学者，缺力量的不会 |
| **好苗子** | **15%** | 一项 12~14，其余 6~9 | 50% 带 1 正面 | 10% 濒死 | **基本都救**，等价于白拿一个酒馆"专家"（1,500 币） |
| **明珠** | **3%** | 一项 15~17，其余 8~12 | 必带 1 正面 | 5% 濒死 | 必救。一周约 **0.5 个** |

> **为什么好苗子只有 15% 而不是 30%**：酒馆"专家"档（主属性 12~14）卖 1,500 币。如果漂流物轻松给到同档，招募系统当场作废。**免费的必须比付费的弱一档、且永远是"偏科"的**——好苗子有一项 12~14，但其余只有 6~9，而酒馆专家是 12~14 + 6~10 + 1 条正面，综合更强。
> **明珠 3%（约两周一个）是刻意的低概率**：它是"今天运气真好"的时刻，不该成为常规供给。等价于白拿 4,000 币的名手，稀有才有味道。
> **拖油瓶 47% 不是凑数**：他们要占 47% 是因为——本作所有岗位都缺人，一个 4 力量的船员也能划桨、能填瞭望台、能在甲板上多挡一刀。**"差的船员也有用，只是不值得花钱买"**，这条区分让招募（买好的）和漂流物（捡剩的）各司其职。

| id | 名称 | 内容 | 类内权重 | 一周次数 |
|---|---|---|---|---|
| G01 | **落难船员** | **1 人**，按 G.1 分布独立 roll | 45 | ≈ 11 |

> **G03（无名浮尸）是唯一"拿钱会痛"的船员类内容**：搜刮给钱但扣 SAN，安葬不给钱但回 SAN。**它是给"SAN 已经很低的人"准备的**——这时候玩家会主动选择安葬，而不是搜刮。这是"选择不拿"成立的少数场合之一（另一处是 E03 浮尸，两者不要在同一次航行里重复出现）。

##### G.3 供给对账（这是"合理概率"的验证）

| 项 | 一周数值 |
|---|---|
| G 类接触次数 | 612 次 × 4% ≈ **24.5 次** |
| 其中"人"的接触（G01 + G02） | ≈ 11 + 13 = **24 人** |
| 按分布：拖油瓶 / 偏科 / 好苗子 / 明珠 | 11.3 / 8.4 / 3.6 / **0.7** |
| **玩家实际会救的人数**（按 10%/40%/80%/100% 的接受率估） | ≈ 1.1 + 3.4 + 2.9 + 0.7 = **8.1 人/周** |
| 酒馆招募（一周约 3~4 次实际购买） | ≈ 3.5 人/周 |
| **一周新增船员** | **≈ 11~12 人** |
| 船员池上限（船体 Lv5、建 10 房） | 10×2 + 7 = **27 人** |

> **结论：一周能填到 11~12 人，两周左右填满上限。** 这个节奏是对的——**第一周靠捡人起步，第二周开始要靠招募优化**。如果一周就填满，招募系统没有存在感；如果两周还填不到一半，玩家会觉得"没人可用"。
> **给补给的接受率没有计入上表**，因为它不产生船员。但它是"低 SAN 时最划算的回收手段"：一周 24 次机会里，即使只救 8 人，剩下 16 次还能各给一次补给（食物 20），换 48 点 SAN。**这是玩家在长章节里维持 SAN 的隐性支柱**，配置时不要把"给补给"的食物成本提到 40 以上。

| 系统 | 关系 |
|---|---|

> **"不同材料表现不同"是这类游戏最重要的一层可读性**：玩家不该读文字才知道捞到的是铁还是木头——**颜色和形状先说话，文字只做确认**。

## 九、装备强化配置表（v1.5：**单一模式 + 四态概率 + 品质升阶**）

> 规则 SSOT 在《装备与锻造系统》§六。本节只给**可配表的数据**。
>
> **v1.5 改了三件事**：① **删除"献祭模式"**——只保留一种强化方式，界面上不再有"稳妥/献祭"开关；② 四态保留（成功 / 升阶 / 破损 / 损毁），但**损毁只出现在 +9、+10 两级**（1% / 2%），+1~+8 永不损毁；③ **按真实期望重算高段成功率**——旧表（+8 50% / +9 40% / +10 30%）的期望不是 84 石而是 **168 石 ≈ 5 周**，与"2.5 周一件 +10"的节奏差一倍，已重调（详见 §9.4 的推导）。

### 9.1 四态概率总表（`enhance_level`，10 行）

**四态互斥，每行合计 100%。"破损" = 等级 −1、装备保留。"损毁" = 该装备从背包直接移除，不可找回、不可修复**（强化等级随装备消失，同名新装备从 +0 重来）。

| 目标 | 石 | 币 | 成功 | **升阶** | **破损（−1 级）** | **损毁（装备消失）** |
|---|---|---|---|---|---|---|
| +1 | 1 | 100 | 100% | — | 0 | 0 |
| +2 | 1 | 140 | 100% | — | 0 | 0 |
| +3 | 1 | 200 | 95% | 2% | 3% | 0 |
| +4 | 2 | 320 | 88% | 2% | 10% | 0 |
| +5 | 2 | 480 | 80% | 3% | 17% | 0 |
| +6 | 3 | 700 | 78% | 2% | 20% | 0 |
| +7 | 3 | 1,000 | 70% | 2% | 28% | 0 |
| +8 | 4 | 1,400 | 62% | 2% | 36% | 0 |
| +9 | 5 | 1,900 | 55% | 1% | 43% | **1%** |
| +10 | 6 | 2,600 | 48% | 1% | 49% | **2%** |
| **合计** | **28** | **8,440** | — | — | — | — |

**实现纪律（三条硬规则）**：

| # | 规则 | 原因 |
|---|---|---|
| 1 | **破损率 = `100% − 成功 − 升阶 − 损毁`，程序算，不许手写** | 任何一格手写都可能让四态加起来不等于 100% |
| 2 | **损毁率在 +1~+8 恒为 0**，程序断言 | 前中段不能有"装备消失"，那是新手劝退点 |
| 3 | **损毁 = 装备被移除 + 返还已投入强化石 50%**（残骸回收），币不退；**不接受"降级代替移除"** | 把"养了三周的东西没了"从"全损"降到"损失半个月"，否则零挫败红线当场破掉。但如果损毁只是降级，那"赌"就没有赌注了 |

> **为什么损毁只放 +9/+10**：+1~+8 是"每个人都要走的路"，路上不能有坑；+9/+10 是"我自己选择再赌一把"的区域，进之前界面会明确写出"2% 装备消失"。**赌的入口必须是玩家自己走进去的，不能是系统塞给他的。**
> **为什么是 1%/2% 而不是 5%/10%**：+9→+10 的期望尝试约 6 次，2% 意味着"一次冲顶约 7% 概率见到损毁"。再高就变成"冲 +10 = 交学费"，玩家会算出来"不划算"，然后整个高段强化没人碰——**这比没有更糟**。

### 9.2 加成表（`enhance_bonus`，乘法）

**公式：`实际值 = 位阶基础值 × 品质系数 × (1 + 0.04 × 强化等级)`**

| 品质 | 品质系数 | +0 | +5 | **+10** |
|---|---|---|---|---|
| 破损 | 1.00 | 100 | 120 | **140** |
| 完整 | 1.12 | 112 | 134 | **157** |
| 精良（绿） | 1.28 | 128 | 154 | **179** |
| 卓越（蓝） | 1.48 | 148 | 178 | **207** |
| 完美（紫） | 1.70 | 170 | 204 | **238** |
| 史诗（橙） | 1.95 | 195 | 234 | **273** |
| 传说（红） | 2.25 | 225 | 270 | **315** |

- 需求减免：`实际需求 = 位阶基础需求 × 品质需求系数 × (1 − 1% × 强化等级)`，最多 −10%
- **`+5 = ×1.20`、`+10 = ×1.40`**，全品质同一倍率——这是"消耗与品质无关"的另一面

**三条必须成立的校验**

| 校验 | 关系 | 意义 |
|---|---|---|
| 同品质单调 | 140 < 157 < 179 < 207 < 238 < 273 < 315 | 强化后仍严格递增 |
| **低品质满强化 > 高品质裸装** | 卓越+10（**207**）> 完美+0（**170**） | **刻意的**：让前期蓝装（卓越）强化后能顶一阵，不至于"拿到紫装前什么都不敢做" |
| **高品质轻强化 > 低品质满强化** | 完美+6（**211**）> 卓越+10（**207**） | **关键的**：紫装 +6 就反超蓝装 +10（不用转移券时的阵痛上限），所以"换紫装"永远有意义 |

> **"同样消耗下强化高品质更划算"是怎么自动成立的**：消耗只跟等级走（+5 恒定 8.8 石 / 1,620 币），而收益乘的是品质系数——同样 8.8 石，卓越从 1.48 涨到 1.776（**+0.296**），完美从 1.70 涨到 2.04（**+0.340**）。**玩家不用看说明，算一遍就知道该先强化谁。**
> **这条设计的代价必须写明**：前期强化蓝装的投入，在换紫装时会被"阵痛"吃掉一部分。处置靠**转移券**（《装备与锻造系统》§6.5）+ 拆解返还 50%，不靠"降低强化成本"——**因为阵痛本身是"该换装了"的信号，抹掉它玩家就不会换装。**

### 9.4 期望消耗对账（这是设计目标，不是展示）

**算法**：`E(L) = 石(L) + (成功+升阶) × E(L+1) + 破损 × E(max(0,L−1)) + 损毁 × E(0)`，迭代至收敛（不是"每级成功率倒数相加"——那个算法漏掉了降级回路，会把成本算低一半以上）。

| 目标 | 期望石 | 期望币 | 一周能做到 |
|---|---|---|---|
| +0 → +5（单件） | **8.3** | **1,485** | **约 4 件全上 +5**（33 石 / 5,940 币，占周产出 7.5%） |
| +0 → +8（单件） | **28.2** | **7,513** | 第 2 周上半 |
| +0 → +10（单件） | **75.9** | **25,332** | **2.2 周**（吃满全部强化石供给） |

> **旧表的 84 石是怎么来的、错在哪**：旧算法把每级成功率取倒数直接相加（`1/0.5 + 1/0.4 + 1/0.3`），**忘掉了"破损降 1 级"的回流**——+8 失败一次要重新爬 +7，而 +7 失败又要爬 +6。带回流算，旧表的真实期望是 **168 石 ≈ 5 周**，和文档里写的"2.5 周"差一倍。这次不是"调数值手感"，是**修正一个算错的账**。
> **现在的节奏**：第一周 4 件 +5（33 石）→ 第二周集中一件到 +8（28 石）→ 第 3 周摸到 +10（76 石，2.2 周口径含重复）。**"跨周目标"仍然成立，但不再是"永远够不到"。**
> **损毁的净成本已计入**：+9/+10 各有 1%/2% 概率打回 +0，这部分已算进 75.9 石里；返还 50% 石是账外的补偿，不重复扣。

### 9.5 品质升阶

| 项 | 规则 |
|---|---|
| 触发 | 判定出"升阶"时，**装备品质 +1 档，强化等级不变** |
| 上限 | **封顶「完美」**。完美及以上（含掉落的史诗/传说）**升阶率强制为 0**，该部分并入成功率 |
| 可升阶起点 | **破损档不可强化**（直接拆解）；完整及以上可升 |
| 升阶后 | 基础值按新品质系数重算，**已投入的等级与石不返还、不重算** |
| 与锻造的关系 | 锻造能**定向**出完美（可控）；强化只能**赌**出完美（不可控）。**锻造仍是"要什么做什么"的唯一路径** |
| 与掉落的关系 | **史诗/传说仍然只能靠掉落**。升阶封顶完美，是为了不破坏"刷宝"这条线 |

> **升阶率的强度核算**：从 +0 养到 +10 约需 21 次强化判定（按 §9.1 新表），各段升阶率均值约 1.5% → **期望升阶 0.32 次**，即约 **1/4 的玩家在养满一件装备的过程中会白得 1 档品质**。
> **为什么是 1~3% 而不是 10%**：10% 会让"完美"变成可量产，锻造和掉落同时失去意义；1% 以下玩家感觉不到，界面上的"升阶率"就成了装饰。**1~3% 是"有彩头、不改变主流路径"的区间。**

### 9.6 界面必须显示的三个数 + 两个提示

| 位置 | 内容 | 格式 |
|---|---|---|
| 概率条 | **成功 / 升阶 / 破损 / 损毁** 四段，颜色区分（绿/金/橙/红） | 四段合计 100%，不做隐藏 |
| 消耗 | 石 ×N、币 ×N | 与概率条同屏 |
| 期望提示 | "当前 +7 → 期望还需约 57 石（含降级回流）" | 只在 +5 以上显示，避免前期太算计 |
| 连败计数 | "已连续失败 3 次，第 5 次后必成功" | 保底可视，防"感觉被系统坑" |
| **损毁二次确认** | +9/+10 点"强化"时弹一次："有 2% 概率装备消失（返还一半强化石）" | **只在有损毁的等级弹**。默认不勾选"不再提示" |

> **"破损率"这个词必须在界面上用玩家能懂的说法**：写"失败将降 1 级（装备不消失）"，不要只写"破损率 43%"。**克苏鲁的恐怖在叙事里，不在让玩家猜术语上。**

### 9.7 验收标准

| # | 项 | 标准 |
|---|---|---|
| 1 | 四态合计 | 每一行 `成功+升阶+破损+损毁 = 100%`，程序断言 |
| 2 | 低段无损毁 | **+1~+8 损毁率恒为 0**；10 万次模拟 0 次损毁 |
| 3 | 乘法校验 | 同品质 +0<+5<+10 严格成立；**完美+6（211）> 卓越+10（207）> 完美+0（170）** |

| 5 | 升阶继承 | 升阶后等级不变，且基础值按新品质重算 |
