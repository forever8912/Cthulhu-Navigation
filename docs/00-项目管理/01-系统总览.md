## 二、核心玩法结构

### 2.1 双层玩法
```
【经营层】船舱横剖面（类辐射避难所）
  - 房间建造/升级，船员拖拽分配岗位
  - 生产：能源（蒸汽吃木材）/食物/淡水/弹药/装备/材料
  - 维持：SAN值、伤病、特性、房间/船体耐久

【战斗层】横版挂机塔防
  - 怪物自远海出现 → 游入射程 → 攀上船舷 → 上甲板 / 入侵舱室
  - 射程分层：炮位几乎全程可打、枪械/法器要等怪靠近、近战必须等它登船
  - **船不白送火力**：第一座塔由玩家自己造（`2001` 鱼叉炮，船体 Lv1 即可建），塔防的"塔"必须是玩家立的（v1.15 删掉原有的舷侧固定炮 ×2）
  - 船员全自动战斗（器械 + 武器），玩家不操作攻击
  - Boss = 大型海怪，需 SAN 抗性达标后挑战
```

### 2.2 玩家操作（1 个高频 + 2 个低频）
**高频操作 = 拖拽船员到具体舱室**，其余全自动：器械自动开火、船员自动攻击、生产自动、探索自动闯关。  
**低频操作 = 2 个主动技能**（每场战斗各 1 次）：**全员参战**（把生产岗拽上甲板，烧食物换火力）、**传送逃跑**（烧能源换退出）。

| 决策点 | 示例 |
|---|---|
| 人事调度 | 快死的拖去医务室、高技巧的拖去损毁房间修理、SAN崩溃的拖去忏悔室、漏怪时拖人补甲板 |
| 主动技能 | 漏怪过多 → 全员参战；判断打不过 → 读条传送逃跑 |
| 建造升级 | 房间建造/升级、船舱扩容 |
| 点击行为 | 锻造、捞漂浮物、主动钓鱼 |

> **已定**：主动技能就这 2 个，不再增加第三个。中间的所有判断（要不要硬撑、先救谁、修哪个房间）全部留给拖拽。

## 三、核心循环与压力轴

```
挂机生产（能源/食物/淡水/弹药）
      ↓
怪物袭击 → 自动防御 → 掉落装备/材料
      ↓
资源投入 → 房间升级 / 装备锻造 / 船员治疗
      ↓
实力增长 → 挑战海域Boss → 通关结算（SAN判定→特性获得）
      ↓
解锁新海域（更强怪物/更高恐惧值）→ 新一轮循环
```

### 3.1 压力轴（4条）
| 压力 | 来源 | 失控后果 |
|---|---|---|
| 能源 | 能源房产出 vs 全船耗能（**v3.6 起全船只有一间能源房：动力舱**） | 全船停摆（总闸） |
| 食物 | 食物房产出 vs 船员消耗（基准 1.0 食物/人/分钟） | 饥饿→SAN下降→效率下降；**同时是「全员参战」的燃料（消耗×3）** |
| **淡水** | 水源房产出（MVP雨水收集器）vs 船员消耗 | 海上核心生存指标：短缺→SAN持续下降 + 种植房停产 |
| SAN | 见《SAN与特性系统》 | 崩溃→停工/debuff→战斗失败 |

### 3.2 三条不计入压力轴的资源
- **弹药**：**炮台（5~8 发/次，物理吃炮弹、魔法吃魔晶）与火枪（1 发/次）共用同一个弹药池**；耗尽则二者哑火——火炮房停火、火枪船员转白刃，**但舷炮（不耗弹）继续工作**。只在战斗界面显示剩余数量，不做压力条。主产地是全船唯一的工坊（40 发/分钟），掉落只占需求约 7%
- **木材**：能源 + 建造 + 修理三重消耗，来源 = 漂浮物/岛屿探索/怪物掉落
- **魔晶**：魔法线专用，来源 = 怪物掉落/岛屿探索

> **弹药为什么不能进压力轴**：压力轴的四条（能源/食物/淡水/SAN）都是"持续流失、必须持续供给"的曲线；弹药是"战斗时瞬时消耗、平静期不消耗"的库存。把库存型资源做成压力条，会让玩家在平静期也焦虑，与"100 秒平静期是用来放松经营"的节奏设计冲突。

## 五、船员与属性

### 5.1 四维属性（已收敛，砍掉敏捷）
| 属性 | 绑定 |
|---|---|
| 力量 | 物理武器伤害（近战/远程）、动力舱 |
| 技巧 | 战斗攻速、科技器械、钓鱼、工坊、瞭望、过滤设备、修理 |
| 智力 | 魔法武器伤害、魔法器械、种植、医务室 |
| 精神 | SAN上限与恢复、恐惧抗性、忏悔室 |

岗位效率 = 船员属性 ÷ 岗位需求属性：达标 100%，超出线性加成、**封顶 200%**。

### 5.2 成长方式
- **属性成长**：对应属性房间工作 / 战斗 / 锻炼室锻炼 / 特定道具 → 该属性经验 → 满值提升属性
- **转职成长**：属性达标 + 转职书 + 完成转职任务 → 转职，获得额外技能与属性提升；共7档，最高"神级"（后续开放），**MVP 开放前3档**
- 辅助：装备（4槽位词缀）+ 特性（通关结算获得）+ SAN状态
- 详见《船员养成系统》

### 5.3 船员上限
- **上限 = 船舱槽位数 × 2 + 甲板战斗岗数**
- 甲板战斗员初始 3 名，船只每升 1 级 +1 战斗岗
- 示例：1级船 3 船舱 → 3×2+3 = 9 人；2级船 6 船舱 → 6×2+4 = 16 人
- 船只升级在**船舱界面**直接进行（v3.2：原"船坞岛"已删，界面随时可做，不该等随机事件）
- 船员获取三条线：**漂流物「落难船员」（免费但偏科，属性决策前可见，可救可给补给可驶离）** + **酒馆/招募界面（花钱买全面型）** + 竞技场（不给船员）
- **免费船员永远"偏科"，全面型只能花钱买**——这条分工不能乱（见《03》§G）

### 5.4 死亡与复活（2026-10-28 修订：死亡不惩罚养成资产）
- **生命归零 = 死亡**：该船员立即脱离战场，本场战斗不再参战，但**不永久移除**
- **复活无次数限制**，三条等价路径任选其一（见下表）

| 复活路径 | 代价 | 说明 |
|---|---|---|
| 激励视频 | 看 1 次广告 | 主路径，无次数上限 |
| 贝壳币 | 固定 200 贝壳币 | 广告填充失败时的兜底，不可被广告卡死 |
| 等待苏醒 | 60 秒后自动复活 | 零成本保底，避免任何卡关 |

- 复活后状态：**SAN 归 30、HP 回 50%**，保留全部特性 / 转职 / 属性 / 装备
- **死亡不失去正面特性、不产负面特性**（原"随机失去 1 项正面特性"已作废）；负面特性唯一来源是 SAN<30 的章节结算
- 战败（船只耐久归零）**不导致任何船员死亡**，只按比例扣血 + 损失部分资源 + 重置章节进度，详见《战斗系统》第六章
- 设计意图：死亡=本场战斗的即时损失（少一个战力、少一份掉落），不是长期资产损失；用"无限复活 + 无特性惩罚"把挫败感压到最低，让玩家敢打敢试

### 5.5 离线规则（单机版核心，v3.0 新增）

**本作是单机游戏，玩家的时间相对集中。离线不是"挂机推图"，而是"船抛锚了在海上漂"。**

| 项 | 规则 |
|---|---|
| 下线行为 | **自动抛锚**，进度存到当前航段（每 500 里一段）起点 |
| 章节进度 | **完全不推进**——不移动距离、不触发袭击、不触发岛屿/Boss |
| 离线战斗 | **不发生**。不会有离线战败、离线死人、离线掉装备 |
| 离线产出 | **打捞物 + 贝壳币 + 鱼获** 三类，见下表 |
| 产出效率 | 在线的 **50%**（船员轮班休息，不是满负荷） |
| 累计上限 | **8 小时**（超过部分不再累计，需上线"解锁"一次） |
| 资源消耗 | 离线期间**不消耗食物/淡水**（抛锚时不下网不划桨，消耗极低，视为 0） |
| 领取方式 | 上线时弹"归航结算"面板，**一次性开箱**（这是每日的核心正反馈） |

**离线产出表（每小时，已含 50% 效率）**

| 来源 | 木材 | 铁 | 贝壳币 | 食物 / 鱼获 |
|---|---|---|---|---|
| 基础漂流打捞（无房间，全船通用） | 12 | 6 | 20 | — |
| 钓鱼房（有人时） | — | — | — | 食物 4 + 鱼获 1 条/小时 |
| 种植房（有人时） | — | — | — | 食物 3 |
| **满 8 小时合计**（含两间房） | **96** | **48** | **160** | 食物 56 + 鱼 8 条 |

> **为什么离线收益必须远低于在线**：在线玩 1 小时战斗产出约 3,000 贝壳币，离线 8 小时只有 160 贝壳币——**相差 150 倍**。这不是数值没调好，而是刻意的：单机游戏的核心体验是"我在的时候船在动"，如果离线能替代在线，玩家就没有理由回来。
> 离线收益的定位是**"上线有东西可收"的仪式感**，不是主要资源来源。它的价值是让"打开游戏"这个动作有即时回报，而不是替代游戏。

**⚠️ 一个必须守住的边界**：离线**不再触发战斗**，意味着玩家不能靠"挂着睡觉"来刷怪刷装备。这与旧版"离线挂机产出"的写法冲突，旧写法已作废。若后续要加"离线远征"，那必须是另一个独立系统，不能挂在主章节上。

## 七、分期路线图

### MVP（8-10周）
- 房间 **13 间**（v3.6 定稿，不含船体）：**动力舱**（唯一能源房，人力→溺亡水手→电鳗→船底那位）、水源房、钓鱼房、种植房、瞭望台、医务室、**4 组炮台**（单体物理 `2001` / 群体物理 `2004` / 单体魔法 `2003` / 群体魔法 `2002`）、**工坊**（船体 Lv2）、**忏悔室**（第 2 章）、**打捞房**（船体 Lv3，0 岗位），外加**船体 `9001` / 生命号船体 `9101`**
- **船体 Lv1~Lv5**（格数 8/10/12/14/16，耐久 150/300/500/750/1050，甲板战斗岗 3/4/5/6/7）
- 船员上限按"已建房间数×2 + 甲板战斗岗"计算（Lv1 建 4 房 → 4×2+3 = 11 人）
- 压力轴 = 能源 + 食物 + 淡水 + SAN（**弹药为库存型资源**：炮台 5~8 发/次、火枪 1 发/次，耗尽是**该炮台**哑火——v1.15 起没有"免费兜底火力"）
- 属性经验（工作/战斗/锻炼室/道具）+ 转职前3档
- **3 张海图，长度递增：1,000 里 / 3,000 里 / 5,000 里**（≈17 / 50 / 83 分钟），每 500 里一个航段检查点
- **节点密度**：精英 2/4/6 个、小Boss 0/1/2 个、大Boss 1/1/1 个 → 共 18 个里程碑怪
- **29 种怪**（海域1~3 原 9 普通 + 5 精英 + 3 大Boss，**下沉复用 3 只 + 精英做 3 个规格变体**补齐到 11 普通 + 8 精英）+ **3 个小Boss**（复用精英模型放大改写，新增美术 = 0）
- **奇迹之海：无限循环三章地图，每 1,500 里一个深度层**，怪物数值按层外推（层 7 起用公式）
- 战斗：**射程分层**（火炮房 95 / 枪械 65 / 法器 55 / 近战 20，见《战斗系统》1.3）+ **火炮房 AOE 溅射** + 船员武器自动攻击；房间/船只耐久与修理；海中怪 + 登船怪；2 个主动技能（全员参战 / 传送逃跑）
- 装备 **4 槽位 × 7 档品质**（破损~传说），掉落 70% / 锻造 30%；钓鱼主动 + 自动；鱼类图鉴 40 种
- **6 类岛屿**：商人岛（17 商品 + 10 事件）/ 遗迹岛（7 主题 × 5 节点，3 人小队，进度条，N1~N4 可撤退）/ 海面奇遇（**20 条，v1.10 已落表 `event_id=2101~2405`**）/ 酒馆岛（12 条）/ **竞技场岛（无限层爬塔，不死亡）** / 神秘商店（7 商品）。**船坞岛与教会岛已删**，理由见《03》§3.0
- 漂流物 10 大类 × 39 模板 + 7 特殊；**落难船员属性决策前可见，救/给补给/驶离三选一**
- **单机离线模型**：下线自动抛锚，进度不推进、不发生战斗，只结算打捞物/贝壳币/鱼获（上限 8 小时）

## 八、商业化约束（硬性）

1. IAA 为主，单日激励视频 ≤5 次，点位受频控
2. 取消一切强制插屏
3. 广告点位：死亡复活 / 离线收益翻倍 / 打捞加速 / 锻造品质保底 / 商人岛刷新 / 再捞一次 / 再抛一竿 / 游戏币获取
4. **分享/广告点位一律"三选一"，不设强制分享**（合规硬要求）：
   任一触发点都必须同时提供「分享 / 看激励视频 / 消耗游戏币」三条**等价**路径，玩家任选其一即可推进；禁止出现"必须分享才能继续/领奖"。
   分享与广告的**默认推荐顺序**按登录天数递减（D1 推荐分享 80/20 → D7 起 20/80，前 3 次默认高亮分享），该比例**只影响默认高亮项与推送权重，不影响可选项是否存在**（详见《日常与留存系统》第五章）
5. **游戏币永远稀缺，但获取主路径是打怪、不是看广告**：锻造/购买/清特性都消耗游戏币；收入结构为战斗掉落 ≈65%、任务 ≈15%、成就与里程 ≈15%、广告 ≈5%。广告只卖"时间与确定性"（离线翻倍、再捞一次、锻造保底），不得通过阻断功能逼迫
6. 恐怖题材与微信用户池存在错位风险：美术上"阴森氛围 + 梗道具名"调和，不做血腥跳吓；买量素材同样分级（微信端避开血腥/跳吓，用"经营建造 + 怪物奇观"包装）

## 程序接入说明（v1.25：`09_全局参数.xlsx`——全局配置）

3 sheet，**最先加载**（其它表解析依赖其中参数）：

- **全局参数表**：key-value + type（int/float/str）。关键键：资源闭环（`life_tick_sec`/`life_food_per_crew`/`life_water_per_per_crew` 系列）、鲸脂（`whale_oil_shots=100`/`whale_oil_dmg_bonus=0.10`）、强化（`enhance_destroy_stone_refund=0.5`）、竞技场（`arena_layer_atk_base` 缺省公式，**权威源在 11 表**）。程序按 key 取值，**禁止硬编码这些数值**
- **通用消耗表**：`cost_id` → `items_json`，供界面复用的标准消耗包（升级弹窗等）
- **广告点位表**：`ad_id` → 场景 + `daily_limit`，商店刷新/打捞加速等接这里

校验：`verify_room.py`（生活参数断言）、`verify_p2.py`（强化返还）。
