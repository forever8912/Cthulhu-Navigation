# 02 - 《恐惧之海》第一章垂直切片开发计划

> 版本：v1.0（2026-10-30）
> 状态：**当前执行计划（SSOT）**
> 适用条件：单人开发、AI 辅助编码与美术、每周稳定投入 35~40 小时、当前尚无游戏工程。
> 覆盖规则：本文件只管理“第一章垂直切片”；三海域内容量、长期经济与商业化仍保留在原 MVP 文档中，但不得提前进入本阶段。

---

## 一、阶段目标

用 12~14 周做出一个可交给外部玩家测试的第一章 Alpha，回答唯一关键问题：

> **“拖拽船员调度 + 船舱经营 + 射程塔防”是否能持续产生有意义的决策？**

第一阶段不以内容量、留存或广告收入作为成功标准。核心玩法没有通过前，禁止批量制作三海域内容。

## 三、Cocos Creator 3.8 适配结论

### 3.1 结论

**Cocos Creator 3.8 LTS 能满足本项目的个人开发需求，适配度评为 8/10。**

适合本项目的原因：

1. TypeScript 一等支持，`strict` 类型检查能降低 AI 生成代码的静默错误。
2. 2D Sprite、UI、图集、对象池、Web 与小游戏发布路径成熟。
3. 同一核心逻辑可复用到 Web、微信与 TapTap 小游戏适配层。
4. 官方支持导出构建配置后从命令行构建，适合自动化验证。
5. 项目不依赖 3D、复杂物理或大型开放世界，不会触及引擎能力上限。

官方资料：

- Cocos Creator 3.8 LTS 手册：<https://docs.cocos.com/creator/3.8/manual/>
- 命令行发布：<https://docs.cocos.com/creator/3.8/manual/en/editor/publish/publish-in-command-line.html>

### 3.2 必须接受的限制

- 命令行构建仍需要图形环境，不能当作完全无编辑器的纯服务器工具链。
- 首个场景、平台构建参数和导出配置需要在编辑器中完成一次。
- 新素材的 `.meta` 生成与导入行为必须在 W1 实测。
- Cocos 2.x 与 3.x 搜索资料混杂，代码审查必须禁止旧版 `cc.*` API。
- 小游戏性能取决于节点数、图集和对象池纪律，不是“用了 Cocos 就自动流畅”。

### 3.3 工程模式：混合式，不走两个极端

采用“**逻辑代码化 + 少量稳定 Prefab**”：

- 纯 TypeScript：战斗模拟、资源循环、状态机、配置、存档、平台接口。
- Cocos 表现层：一个主场景 + 船员卡、房间格、怪物节点、HUD、事件弹窗等少量 Prefab。
- 业务逻辑层禁止持有 `Node`；只向视图发送纯数据快照。
- 禁止大规模手工拖引用，但不为“零 Prefab”额外编写大量布局代码。
- 战斗逻辑必须能脱离 Cocos 运行单元测试。

## 五、核心验收指标

| 指标 | 目标 |
|---|---|
| 第一炮开火 | 开局 150~180 秒内 |
| 普通遭遇时长 | 25~40 秒 |
| 精英遭遇时长 | 45~60 秒 |
| Boss 时长 | 90~150 秒 |
| 单场有效调度 | 1~2 次，不靠无意义频繁拖拽凑数 |
| 无决策空窗 | ≤90 秒 |
| 拖拽成功率 | ≥90% |
| 目标机帧率 | ≥50fps，最低不得长期低于 45fps |
| 首章时长 | 20~30 分钟 |
| 外测独立通关 | ≥70% |
| 外测继续意愿 | ≥60% |

## 六、止损规则

1. 任一功能连续 2 个工作日没有可运行画面，立即缩到最简形态。
2. 单项超过估算 1.5 倍，不加班，用同体量功能换出。
3. 每周必须有一个可启动版本；失败则下周禁止新增功能。
4. W2 灰盒若不能证明调度有决策价值，不进入内容生产。
5. W10 厚涂母版未通过，不得批量生成资产。
6. 新增任何系统，必须从当前阶段删掉一个同体量系统。

## 八、阶段完成后的决策

W12~W14 只允许三种结论：

1. **继续**：核心指标通过，进入第一章上线版。
2. **重做核心**：题材和美术保留，重做调度或战斗节奏。
3. **停止**：拖拽无法形成决策，避免继续投入三海域内容。

三海域 1.0 预计仍需在本阶段之后追加约 5~8 个月，必须重新估算，不自动继承旧排期。
