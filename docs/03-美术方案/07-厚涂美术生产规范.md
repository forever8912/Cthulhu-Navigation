# 07 - 《恐惧之海》厚涂美术生产规范

> 版本：v1.1（2026-10-31）
> 状态：**当前美术生产 SSOT，可持续迭代**
> 适用范围：概念图、船体、房间、角色、怪物、特效、背景、UI 图标及 AI 生成记录。
> 上位决策：暗黑厚涂是唯一量产风格；96~128px 逻辑显示尺寸；角色和怪物优先部件化动画。

---

## 一、风格目标

### 1.1 一句话风格

**低饱和深冷色的暗黑航海厚涂；人造船体温暖、粗粝、可用，海与怪物潮湿、冰冷、未知。恐怖来自压迫和代价，不来自血腥与跳吓。**

### 1.2 必须保持

- 可见但不过度凌乱的油画笔触、干刷边缘和厚重明暗。
- 主光源默认来自左上；同一场景不得随资产改变光向。
- 大面积低饱和蓝绿、灰黑、旧木褐；高饱和色只作功能信号。
- 材质必须可辨：湿木、锈铁、盐渍、藤壶、麻绳、旧帆布、黏液。
- 船上空间仍保留人类生活痕迹和局部暖光，避免整张图只有黑色。
- 怪物先读剪影，再读眼睛/触手/甲壳等特征，最后读表面细节。
- UI 和战斗资产必须优先服务可读性，不能为了氛围遮住交互信息。

### 1.3 禁止风格漂移

- 低分辨率像素风、马赛克滤镜、赛璐璐、Q 版、可爱化。
- 粗黑卡通描边、纯矢量平涂、霓虹赛博朋克。
- 真实照片、写实摄影、塑料 3D 渲染、默认 Unreal 质感。
- 大面积鲜红血液、残肢、尸体特写、宗教祭祀和跳吓画面。
- 直接模仿具体在世艺术家或受保护游戏/影视 IP 的画风。

### 1.4 已批准场景母版

- `assets/风格定稿/风格定稿.png` 登记为 `STYLE_SCENE_001_v001`，是第一章船上主场景的已批准视觉母版。
- 该母版优先锁定：横版船体剖面构图、冷海暖船的色彩关系、旧木/锈铁/麻绳材质语言、海雾纵深、局部灯火、交互主体对比和铜木 UI 装饰语言。
- 该母版不直接锁定：最终房间尺寸、碰撞区域、动画锚点、部件数量、遮挡后的结构、运行时分辨率和正式 UI 布局。
- 母版允许在交互主体、船体结构和 UI 框架上使用有粗细变化的深色结构边，但禁止演变为均匀粗黑卡通描边。
- 场景可使用冷色环境光与暖色局部灯并存；独立资产仍需保存中性光照审核版，合成时再按场景补局部光，避免把不可复用的整场光影烘焙进所有部件。
- 禁止直接从扁平母版抠取被遮挡或需要动画的部件作为正式运行时资产。必须按共同画布、完整结构和统一锚点正向重绘，并通过回拼图验证。
- 具体拆分、首批交付和回拼闸门见 `08-风格定稿与拆分素材制作计划.md`。

## 二、色彩、光照与材质

### 2.1 核心色板

| 用途 | 建议色 | 规则 |
|---|---|---|
| 深海暗部 | `#0B0E14` / `#101923` | 不用纯黑堵死层次 |
| 雾与冷灰 | `#334754` / `#61737A` | 背景对比低于交互主体 |
| 旧木 | `#4A342B` / `#74513B` | 船体主材，允许暖灰高光 |
| 锈铁 | `#493A35` / `#8A5A43` | 禁止高饱和橙铺满 |
| 磷光青 | `#4FD1C5` | 怪物、魔法、可交互危险信号 |
| 灵紫 | `#A78BFA` | SAN、异常与稀有提示；不能与青色同时滥用 |
| 人类暖光 | `#D9A65A` | 船舱灯、可恢复/安全区域 |
| 危险提示 | `#C85A54` | UI 与局部受击，不作血浆表现 |

色板是方向约束，不要求所有图片严格索引色。单个普通资产建议控制在 24~48 个主要感知色阶，避免无意义彩噪。

### 2.2 光照规则

- 默认主光：左上 35°~50°。
- 暗部保留材质信息，主体最暗区域仍应与背景分离。
- 自发光只影响附近小范围，不允许全身泛霓虹。
- 同组部件必须在同一光照条件下生成和修整。
- 换色变体只能改变局部色相，不改变体积光影和材质。

### 2.3 层级规则

```text
交互主体 / 危险目标       对比最高、边缘最清楚
船体 / 房间               中高对比、材质可读
近景海浪 / 雾             中低对比
远景 / 天空 / 剪影        最低对比、减少细节
```

## 三、技术规格

### 3.1 尺寸原则

“96~128px”指游戏中的逻辑显示尺寸，不是 AI 生成尺寸。

| 资产 | 生成/绘制母版 | 运行时纹理建议 | 游戏显示尺寸参考 |
|---|---|---|---|
| 普通船员/普通怪 | 1024×1024 透明或中性底 | 192~256px 高，按内容裁切 | 96~128px 高 |
| 精英怪 | 1024~1536px 方图 | 256~384px 高 | 128~192px 高 |
| Boss | 1536~2048px | 512~1024px，允许拆多图 | 画面高度 25%~45% |
| 房间模块 | 1024px 以上，正侧视 | 256~512px | 1 个舱格或 2 个舱格 |
| UI 图标 | 512×512 母版 | 64/96/128px 多档 | 32/48/64px |
| 战斗背景 | 2560×1440 或更高 | 1280×720 分层输出 | 全屏 |

- 优先使用 2 倍纹理显示，缩放必须保持整数或稳定比例。
- 运行时资源必须裁掉透明空白，但部件组可保留统一画布和原点。
- 同一类别的逻辑尺寸和镜头比例由母版锁定，禁止单张图随意变大。

### 3.2 输出格式

- 源文件：保留可编辑分层格式（PSD/KRA/Clip 等）或独立部件 PNG。
- 审核图：PNG，带统一中灰或场景预览底；不得只交 JPG。
- 运行时：透明 PNG/WebP 由引擎测试决定，Alpha 边缘必须干净。
- 背景至少拆为远景、中景、近景/雾三层。
- 禁止把文字、水印、尺寸标注烘焙进运行时图片。

### 3.3 锚点与朝向

- 船员：脚底中心为主锚点，默认面向右。
- 海中怪：身体与水面接触点为主锚点，默认朝向船体。
- 登船怪：脚底/触手接触面中心为主锚点。
- 炮位：底座中心为锚点，炮口方向单独记录。
- 部件动画的所有部件必须共享同一逻辑画布、原点和缩放基准。
- 左右翻转由程序处理时，非对称文字/标记必须单独拆层。

## 四、部件化动画规范

### 4.1 最小部件集

普通角色/怪物建议：

```text
body                    主体
head                    头部，可选
front_limb / back_limb  前后肢或触手
weapon                  武器/攻击器官
fx_glow                 发光层，可选
fx_hit                  命中遮罩/高光，可选
shadow                  阴影或水面接触，可选
```

普通单位原则上控制在 4~8 个可动部件；超过 10 个必须证明游戏内收益。

### 4.2 状态要求

| 状态 | 最低表现 |
|---|---|
| idle | 呼吸、轻摆、船体/海浪带来的微动 |
| move/swim | 主体位移 + 肢体相位变化，不要求逐帧游泳 |
| attack | 0.15~0.35s 预备、明确攻击瞬间、0.2~0.5s 回收 |
| hit | 轮廓闪亮/偏移/局部高光，持续短，不全屏闪红 |
| death/defeat | 失去张力、下沉/散开/化雾；避免尸体特写 |

只有命中火花、炮口焰、短水花等 2~4 帧特效允许使用短逐帧序列。

### 4.3 动画验收

- 攻击前摇必须能被看懂，不能只靠数值扣血。
- 以 1× 游戏速度观看，攻击方向和命中目标清楚。
- 缩到实际显示尺寸后，部件接缝不闪烁、不露底。
- 动作不能改变角色体积和辨识特征。
- 同屏 10 个单位时仍保持可读，不依赖高频全身特效。

## 五、目录、命名与版本

### 5.1 目录

```text
assets/production/
├── source/        # 原始生成图、分层源文件、参考图
├── manifests/     # 生成参数、授权与编辑记录
├── review/        # DRAFT/REVIEW 审核图和对照板
├── approved/      # 已批准的高质量源资产
└── deprecated/    # 旧版本，保留追溯

E:/devfearfulsea/NewProject/assets/art/
├── characters/
├── monsters/
├── rooms/
├── ships/
├── backgrounds/
├── effects/
└── ui/
```

只有状态为 `APPROVED` 或 `IN_GAME` 的资产可以进入 `E:\devfearfulsea\NewProject\assets\art\`。

### 5.2 文件命名

统一使用小写 ASCII、下划线和三位版本号：

```text
mon_0101_body_idle_v003.png
mon_0101_tentacle_front_v003.png
crew_0001_body_v002.png
room_1001_lv1_base_v004.png
ship_9001_lv1_hull_v002.png
bg_sea01_far_v001.png
ui_icon_ammo_v002.png
```

- ID 必须对应配置表；禁止用“最终版”“新版2”“ok”等名称。
- 资产升级不覆盖旧文件，版本号递增。
- 运行时若需要稳定路径，由 manifest 或资源映射表指向当前批准版本。

## 六、AI 生成记录

每次候选生成必须在 manifest 中记录：

```json
{
  "asset_id": "mon_0101",
  "version": 3,
  "status": "REVIEW",
  "purpose": "first-sea normal monster",
  "prompt": "...",
  "negative_prompt": "...",
  "model": "...",
  "model_version": "...",
  "seed": "...",
  "references": ["..."],
  "generated_at": "2026-10-30T00:00:00+08:00",
  "generator": "...",
  "manual_edits": ["separated front tentacle", "repainted left rim light"],
  "license_notes": "self-generated; no protected-IP reference",
  "reviewer": "",
  "review_notes": ""
}
```

- 缺 seed 的平台必须保存任务 ID、原图和完整提示词。
- 使用参考图时必须记录来源和使用权限。
- 禁止把登录 session、token 或账号信息写进 manifest。
- 生成记录与源图一同版本化；运行时包不携带这些元数据。

## 七、生产流程

### 7.1 状态机

```text
BRIEF → DRAFT → REVIEW → APPROVED → IN_GAME
                    ↘ REWORK
APPROVED / IN_GAME → DEPRECATED（被新版本替代时）
```

### 7.2 每个资产的步骤

1. **Brief**：确定功能、显示尺寸、剪影、材质、光向、部件和验收图。
2. **母版对齐**：引用同类别已批准母版，禁止只读文字提示词开工。
3. **候选生成**：通常 3~6 个候选，不做无上限抽卡。
4. **选择剪影**：先缩到实际尺寸评审，再看大图细节。
5. **人工修整**：统一结构、光向、材质、手脚/触手、透明边缘和部件接缝。
6. **拆件**：按共同原点输出部件，补被遮挡区域。
7. **审核板**：中灰底、游戏场景底、实际尺寸、黑白剪影四视图。
8. **入游戏验证**：动作、锚点、遮挡、帧率和图集检查。
9. **批准**：更新 manifest 状态并复制运行时版本。

### 7.3 批量生产闸门

以下母版未批准前禁止批量生产：

- 1 名普通船员。
- 1 只普通怪、1 只精英怪、1 只 Boss。
- 1 间生产房、1 间战斗房。
- 船体 Lv1 战斗主界面。
- 1 组 UI 图标与 1 个事件弹窗。

母版改变时必须评估已经生产的资产，不得默认全量重做或默认全部兼容。

## 八、验收清单

### 8.1 通用

- [ ] 实际显示尺寸下 1 秒内能辨识类别和敌我。
- [ ] 剪影没有与已批准单位高度重复。
- [ ] 左上主光一致，暗部不糊成一块。
- [ ] 材质读得出木/铁/甲壳/肉质/布料差异。
- [ ] 无文字、水印、签名、异常肢体和明显 AI 融合错误。
- [ ] 无血腥、尸体、祭祀和受保护 IP 特征。
- [ ] 缩图后重点仍清楚，没有只在大图有效的细节。
- [ ] 文件名、版本、manifest、ID 与目录正确。

### 8.2 部件资产

- [ ] 所有部件原点、缩放和光向一致。
- [ ] 被遮挡区域已补全，旋转时不露透明洞。
- [ ] 接缝在 idle/attack/hit 三种动作中不闪。
- [ ] 部件数量符合性能预算。

### 8.3 背景与界面

- [ ] 怪物出现线、攀爬路径、炮门和交互区不被背景细节遮挡。
- [ ] 前中远景可独立移动或调色。
- [ ] HUD 安全区内对比充足，雾效不会盖住文字和资源预警。

## 九、反馈与返工

反馈必须描述可观察问题，不使用“感觉不对”“再高级一点”等空泛语言。

```text
资产 ID/版本：
评审场景与显示尺寸：
问题分类：剪影 / 光照 / 材质 / 色彩 / 部件 / 可读性 / 合规 / 性能
观察到的问题：
期望结果：
必须修改：
可选建议：
参考母版：
```

单轮最多指定 3 个“必须修改”项。连续 3 轮仍无法通过时，停止微调并重新审视 Brief 或生成路线。

## 十、规范迭代

- 本规范是活文档，但不可被单个美术 Agent 静默修改。
- 新规则先在 1~3 个资产上试行，通过后再升为强制规则。
- 每次修改记录：原因、受影响资产类别、是否需要迁移、是否影响已批准资产。
- 默认不追溯返工 APPROVED 资产；只有造成玩法不可读、技术错误或合规风险时才强制迁移。
- 风格方向变化属于 R3 变更，必须由用户/主理人确认。

### 10.1 变更记录

| 版本 | 日期 | 变更 | 影响 |
|---|---|---|---|
| v1.1 | 2026-10-31 | 登记 `STYLE_SCENE_001_v001`，明确场景母版作用、结构边和正向拆分规则 | 新拆分资产立即执行；不要求历史提示词自动返工 |
| v1.0 | 2026-10-30 | 确立厚涂、部件化、尺寸、目录、manifest、状态机和验收规则 | 新资产立即执行；旧提示词表保留作参考，不要求自动返工 |

### 10.2 待实测项目

- 普通单位运行时纹理最终使用 192px 还是 256px。
- PNG 与 WebP 在目标小游戏平台的体积、Alpha 边缘和加载差异。
- 部件数量对 Draw Call 的实际影响与最优图集分组。
- 厚涂资产在最低目标机型上的内存峰值。
- 具体目标机型、屏幕安全区与 UI 字号下限。
