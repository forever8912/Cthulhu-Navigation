## 一、读取规则（最小读取原则）

### 1.1 新对话开场三步
1. **读本文件**（文档索引与协作规范）
2. **读《系统总览.md》**（只看与本次任务相关的章节，不必全文）
3. **按"三、变更影响矩阵"打开对应文档**

### 1.2 硬性约束
- ❌ **禁止**一次性 Glob/LS 全目录并逐个 Read 所有文档
- ❌ **禁止**读取状态为"作废"的文档去理解玩法（仅当需要查历史数值/素材时才读，并在结论中说明来源已作废）
- ❌ **禁止**在未读目标文档的情况下直接修改
- ✅ 一次任务涉及的文档数量**控制在 1-4 份**；超过 4 份说明任务拆分粒度不够，应先与用户确认范围
- ✅ 跨文档改动后，必须回来更新本文件的"变更影响矩阵"或相关行

### 1.3 检索优先
需要定位内容时用 **Grep + 关键词**（文档内搜索），不要为了找一句话读整篇文档。

## 五、修改工作流

### 5.1 标准流程
```
1. 读本文件 → 定位"变更影响矩阵"行
2. 只读"必读"列文档（Grep 定位段落，不全读）
3. 明确改动范围，向用户确认（若涉及数值/分期/推翻既有决策）
4. 修改定义处（SSOT）
5. 检查"需同步"列，逐项更新引用处
6. 若新增/作废文档，更新本文件 §2 与 §3
7. 回复中列出"改了哪些文件、哪些留待定"
```

### 5.2 标注约定（文档内统一使用）
- `【待定】` — 已识别但未定的设计点
- `【MVP】/【1.1】/【2.0】` — 分期标注
- `【作废】` — 该段已被新方案取代
- 数值若为占位：写 `（占位，待数值表）`

### 5.3 决策不可静默推翻
已由用户确认的决策（见本文件 §6），任何修改必须先提出、得到确认后才可执行。
