## 一、引擎选型：Cocos Creator 3.8 LTS + TypeScript

### 1.1 结论

**用 Cocos Creator 3.8.x LTS + TypeScript，并且只用 3.8，不要升 3.9。**

### 1.2 为什么是它

| 维度 | 判断 |
|---|---|
| 微信小游戏支持 | **原生一键发布**，编辑器内置分包配置、`project.config.json` 自动生成。这是所有引擎里唯一"官方一等公民"的路径 |
| 包体 | 引擎插件裁剪后约 **1.5MB**，主包 4MB 限额下留出约 2.5MB 给资源——这直接决定你能不能把第一章的怪全塞进主包 |
| 语言 | TypeScript 一等公民。**强类型对"全 AI 写代码"是刚需**，不是加分项：AI 生成的代码靠编译器兜底，比靠人眼审 300 行有效得多 |
| 渲染 | 针对微信 WebGL 做过专项优化（自动合批、状态切换收敛），2D 精灵批处理成熟 |
| 成本 | MIT，免费商用，无分成、无启动屏强制 |
| 生态短板 | 英文文档薄、社区小、**搜索结果里混着大量 Cocos2d-x（已废弃 runtime）的旧 API** —— 这是 AI 幻觉的主要来源，见 §2 |

### 1.3 为什么不选别的

| 候选 | 否决理由 |
|---|---|
| **Cocos Creator 3.9** | 引入实验性 URP 管线，**微信小游戏环境不支持 Compute Shader，开启直接报错**。3.8 是官方标注 Mini Game "Production Ready" 的 LTS |
| **Unity** | 转 WebGL 包体 10MB+，启动慢，4MB 主包红线直接出局 |
| **Phaser 3 + TS** | AI 友好度其实**最高**（纯代码、零编辑器资产、API 十年稳定、语料最丰富），但微信适配要自建（分包、图集、音频、生命周期、SDK），约 5~8 人日，且出问题没有官方兜底。**单人项目承受不起"没人帮"的坑**。若你后续发现 AI 写 Cocos 的幻觉率高到无法忍受，这是唯一值得换的备选 |
| **LayaAir 3** | 社区萎缩，AI 语料更少 |
| **自研 Canvas** | 8~10 个月的项目，自研合批/回收/资源管理 = 自杀 |

### 1.4 版本与工程基线（第一天就定死）

- Cocos Creator **3.8.x LTS**，TypeScript，`strict: true`
- 目标平台：微信小游戏（WebGL），关闭 3D / 物理 / Spine / TiledMap 等未用模块
- 逻辑帧 **20Hz**（50ms tick）+ 渲染插值；不用 60Hz 全量 AI
- 主包只装 `ui_common` + `ship_rooms` + `battle_ch1`；ch2/ch3 走分包

## 二、"全部由 AI 写代码"的硬约束（这一节比选引擎更重要）

### 2.1 最大的坑：AI 不会操作编辑器

Cocos 的常规工作流是"编辑器里拖节点、挂组件、拖引用"——**这些是 GUI 操作，AI 写代码做不了**。如果你按教程的常规方式做，会陷入"AI 写完代码，你还得手工连 200 根引用线"的死循环。

**解法：全代码驱动（Code-First）**

| 做法 | 具体要求 |
|---|---|
| 场景 | 全项目**只保留 1 个空场景**（一个 Canvas + 一个空根节点），其余全部由 TS 运行时创建 |
| 节点树 | 每个界面写一个 `XxxView.ts`，在 `onLoad` 里用 `new Node()` + `addComponent()` 构建 |
| 组件注册 | `@ccclass('RoomNode')` 注册，靠 `node.addComponent(RoomNode)` 动态挂，**不在编辑器里拖** |
| 引用 | 一律代码注入（构造参数或 `setData()`），**不用 `@property` 拖引用**（拖引用是 AI 无法完成的部分） |
| Prefab | 不使用。重复元素走对象池 `RoomNodePool.acquire/release` |
| 布局 | 手写 `Widget`/`Layout` 参数，或自己做一套锚点定位工具函数 |

代价：UI 代码量比拖拽方式多约 30%。收益：**AI 可以 100% 接管**，且合并冲突、场景文件损坏（`.scene` 是易冲突的 JSON）全部消失。对单人项目这笔账是赚的。

### 2.2 六条编码纪律（写进项目根 `CLAUDE.md`）

1. **规格先行**：先让 AI 写 `interface` + 类型 + 失败用例，人确认无误，再让它写实现。没有类型的实现不接收。
2. **单文件 ≤300 行**：超过就拆。AI 的修改精度随文件长度快速下降。
3. **一次一个可验证需求**：每次提需求附带"怎么算做对了"。例如"实现拖拽放到舱室，验收：松手后船员出现在该舱室，血条位置跟随"。
4. **三处必须人审**：存档迁移函数、微信 SDK 封装、构建/分包配置。这三处改错最难查、后果最重。
5. **每天 commit**：AI 改坏了能回滚，这是单人项目唯一的保险。
6. **禁用 API 清单**：把常见的 Cocos 2.x 幻觉 API（`cc.Sprite`、`cc.Node` 全局、`cc.director` 旧调用）列成黑名单写进 `CLAUDE.md`，并要求"只用 import 形式"。

### 2.3 `CLAUDE.md` 必写的 8 条

```
1. 引擎：Cocos Creator 3.8.x LTS + TypeScript strict，禁止使用 2.x / Cocos2d-x 写法
2. 只用 import { _decorator, Component, Node, Sprite } from 'cc'，禁止全局 cc.*
3. 禁止在编辑器拖引用；所有节点运行时创建；禁止使用 Prefab
4. 逻辑与视图分离：逻辑层不发 Node 引用，只发纯数据快照
5. 事件必须 on/off 成对，统一在 onDisable 里 offAll()
6. 循环内禁止 instantiate/destroy，走对象池
7. 配置只从 config/*.json 读，禁止硬编码数值
8. 每个模块提交前必须通过：tsc --noEmit + 该模块的单测
```

## 三、AI 编码工具推荐

### 3.1 推荐组合（两只，不要装四只）

| 角色 | 工具 | 理由 | 成本（2026-08 官网口径，以官网为准） |
|---|---|---|---|
| **日常主力** | **TRAE**（字节） | VS Code 同源，配置/插件/快捷键一键导入；中文需求理解在一梯队，口语化描述能直接落到代码；Builder 模式可生成项目骨架；基础版免费 | 基础版 **免费**，Pro 按需 |
| **攻坚/重构** | **Claude Code** | 复杂跨文件重构、架构设计能力最强，能读整个工程后改多处；终端形态适合"我说需求它跑测试" | 按量计费，重度使用约 $100~200/月 |
| _可选补全_ | Cursor | Composer 多文件编辑体验最好，但 $20/月且与 TRAE 功能重叠 | $20/月 |
| _国产合规备份_ | 通义灵码 | 个人版免费、国内直连稳定、中文注释质量好；Agent 能力偏弱，适合当"高级补全" | 个人免费 |

**给你的建议**：先只用 **TRAE 基础版** 跑完 S0 和 M0 灰盒（约 2 周）。如果发现跨文件重构吃力，再加 Claude Code 专项攻坚。**不要一开始就三四个工具并存**——单人项目最贵的是切换成本。

> 说明：以上价格与能力评级来自 2026 年 8~10 月的第三方横评与官网口径，属**参考信息**，实际以官网为准；我没有实测这些工具在本项目上的表现。

### 3.2 AI 编码的真实效率预期

- 常规业务逻辑（状态机、UI 构建、配置读取）：**AI 可完成 80~90%**，人做验收与修正
- 引擎 API 调用密集处（渲染、资源加载、微信 SDK）：**AI 一次通过率明显下降**，因为 Cocos 3.x 与 2.x 语料混杂
- 算法/数学（伤害公式、缩放管线）：AI 强，但**必须写单测**，否则错误会静默传播
- **不要指望 AI 做架构决策**：模块边界、数据流方向、技术债取舍必须你自己定，AI 会把架构越写越乱

**结论**：50h/周里，真正"人写代码"的时间可能只有 5~8h，其余是**写规格、审 diff、跑验证、修 AI 的幻觉**。这不比手写轻松，但产出高 3~5 倍。

## 四、排期重算（50h+/周）

### 4.1 口径

- 50h/周 ÷ 6h（1 人日）= 8.3 人日/周；考虑长期高强度疲劳与任务切换，**按 7 人日/周**保守计
- 总工作量 240 人日（工程 175 + 美术 55 + 内容条目 10）
- 纯执行 240 ÷ 7 = **34 周**；加 20% 缓冲（提审、返工、生病、AI 卡壳）= **41 周**
- 区间：**36~43 周（约 8.5~10 个月）**

### 4.2 为什么比"10~13 个月"短了

上轮按 40h/周全职算得 42~55 周。现在 50h+ 且接受分期，实际收益有两块：

1. 每周多 10h ≈ 多 1.7 人日 → 约省 5~6 周
2. 分期让 S2 结束时就有可上线版本，后面的 S3 是"边运营边开发"，主观周期感大幅缩短

但要说清楚：**50h/周持续 9 个月，是单人项目的高危区间**。参考 §7 的止损条款，别硬扛。

## 七、每周闸门与止损

### 7.1 周闸门（每周日必过）

- [ ] 本周有**能在手机上启动**的版本
- [ ] 本周 commit ≥4 次，且每次可回滚
- [ ] `tsc --noEmit` 零错误
- [ ] 新增代码有对应验证方式（单测或真机步骤）
- [ ] backlog 净增 ≤0（新增功能数 ≤ 完成功能数）

**任一项不满足 → 下周禁止新增功能，只还技术债。**

### 7.2 五条止损规则

| 规则 | 触发条件 | 动作 |
|---|---|---|
| A 两天规则 | 任一功能连续 2 个工作日无真机产出 | 砍到最简形态 |
| B 1.5 倍规则 | 某块预估被突破 1.5 倍 | 不加班，从 backlog 尾部砍等体量功能 |
| C 1:1 换出 | 想新增功能 | 先删等体量或更大的现有功能 |
| D 周闸门 | 见上 | 只还债 |
| E 路径判据 | 不在"通关第 1 章"链路上 | 不进 MVP |

### 7.3 三个"最可能死"的预警

1. **W5~W6 船舱横剖面**：若 W5 结束仍无"拖入舱室→进度条动起来"的画面 → 立刻降级为网格贴图版（去逐帧动画、去斜视角）
2. **W17~W19 事件引擎**：连续 3 天只在写解析器、没有一条 choice 在真机跑通 → 数据模型选错，退化为"线性选项→结果组映射"
3. **任意阶段**：连续 2 周没有可启动版本 / 同一验收判据被自己改第 2 次 → 范围膨胀，执行 D 规则
