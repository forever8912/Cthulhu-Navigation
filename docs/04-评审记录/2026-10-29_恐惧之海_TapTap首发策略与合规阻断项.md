## 0. 阻断级发现：TapTap 内容规范直接命中本项目的题材

【官方文档引用·member-6 检索】《小游戏内容规范》原文条款：

- **"不得以政治、恐怖、宗教、性少数群体等争议议题作为游戏核心题材或宣传点"**
- **"禁止过于恐怖的角色（如扭曲五官、诡异动作）或场景（如阴森音效、密集恐惧元素）"**
- **"禁止残肢、尸体、骷髅、内脏暴露"**
- **"角色死亡后，尸体需在 5 秒内消失或转化为不可交互物体"**

**这意味着 TapTap 首发没有消除题材错配，只是把"微信用户池错配"换成了"平台审核口径错配"——后者更硬，会被直接拦截。**

| 本项目现有设定 | 命中条款 | 处置 |
|---|---|---|
| 对外名《恐惧之海》/ 内部名"恐怖大航海" | 恐怖作为核心题材与宣传点 | **改名**，对外名不得含"恐怖/恐惧"字样 |
| 克苏鲁恐怖定位 | 争议议题作核心题材 | **降级为"深海悬疑 / 克苏鲁式探索"**，商店页禁用恐怖卖点 |
| 溺亡者 / 食尸者 / 棺中王 | 尸体、内脏、禁恐怖角色 | 沿用改名（啃船者 / 铅匣之王）+ 逐条自查 |
| 遗迹"沉没教堂 / 祭坛 / 血信徒" | 宗教与崇拜意象、血 | 沉没钟塔 / 黑石台座 / 潮声会众 → **"潮声会众"仍属崇拜意象，建议再降为"潮汐观测会"**，删献祭与祭祀文本 |
| 船员死亡、触手群、血迹、闪红、jumpscare | 尸体表现、密集恐惧、引人不适 | 死亡后 5 秒内消失或转不可交互物；触手群控制密度；**禁 jumpscare 与阴森音效** |

⚠️ **这不是"优化建议"，是上线前的准入条件。**好消息是它与上一轮市场评估的结论同向（建议把恐怖从"惊吓"改为"代价"），现在只是从"建议"升级为"强制"。

## 1. 主理人裁决

### 裁决 1：首发走 **TapTap 小游戏**，不走原生 APK
依据（member-5）：
- Cocos 3.8 **有现成发布模板**：按微信小游戏构建 → 勾选"转换为 Tap 小游戏" → 二阶段自动转换，产物 `build/TapBuild/game.zip`。**一次构建双端出包**，增量仅 0.5~1 人日
- TapTap 小游戏引擎适配文档只列 Unity 与 Cocos/Laya/Egret，其中 **Cocos 插件 `tap-minigame-ts` 仅支持 3.8.x 及以上** —— 与我们已选版本正好吻合
- 原生 APK 需 JDK17 + Android Studio + SDK/NDK + CMake + Gradle + 自签 keystore，**磁盘 11~20GB、一次性 9~12 人日（零基础系数后）**，且必然踩 2~4 次英文堆栈坑（NDK 版本错配、Gradle 下载失败、依赖冲突，每次 0.5~2 天）

### 裁决 2：**不换引擎**，Cocos 3.8.x LTS 保留
4MB 约束消失**只对 APK 路径成立**；走 TapTap 小游戏，包体纪律仍需保留（见 §6）。换 Godot 等于重付整个 S0（引擎学习、全代码驱动约定、6 个 bat、自检页规范），换 Unity 更贵且包体劣势。沉没成本换不来等量收益。

### 裁决 3：路径选择押后到 **W14**
S1 仍先做 Web 版验证玩法。**在 S1 验收通过时再定 TapTap 小游戏 vs APK**——因为 S1 的可玩性结果会改变你对投入的判断（不好玩就别投 Android 环境）。

## 2. 首发策略对比

| 维度 | **TapTap 小游戏首发**（推荐） | 微信小游戏首发 | 双端并行 |
|---|---|---|---|
| 题材匹配 | 核心玩家接受克苏鲁，但**内容规范明禁恐怖为核心题材** | 用户池错配（上一轮结论） | 两端风险叠加 |
| 准入门槛 | 个人主体可认证；无内购**无需版号**，须完成"小游戏前置备案" | 个人主体流量主权限需确认 | 双份资质 |
| 零基础可操作 | **高**：纯小游戏形态下防沉迷由平台默认开启，开发者无需自接 | 中 | 低 |
| 变现 | IAA 官方 **100% 现金分成**（Dirichlet / TapADN），平台不抽成 | 需实测 | 高但成本翻倍 |
| 迭代 | 篝火 / 预约 / 限量测试工具链完整 | 快 | 慢 |

**【推荐】TapTap 小游戏单端首发，微信延后至第二端。**前提：立项文案把恐怖降级为深海悬疑，商店页不得主打恐怖。

## 3. 无版号路径的可行边界（1 人零基础个人主体）

### 官方口径（developer.taptap.cn，2026-10 检索）
- ✅ 不涉及内购的小游戏**无需版号**，但正式上线前须完成**"小游戏前置备案"**（整合小游戏备案 + ICP 核准）
- ✅ "敬请期待 / 预约"状态不要求包体与资质，**可以现在就建页蓄水**
- ✅ 纯小游戏形态下防沉迷由平台默认开启，开发者无需操作（**一旦同时提供 APK 则必须自接**）
- ✅ 首包 ≤60M+，必须接入 TapTap 登录
- ✅ IAA 必须接入 Dirichlet（TapADN），100% 现金分成

### ⚠️ 来源冲突（必须知道）
- 某代办资质站称"TapTap 所有游戏含测试服均需版号"——**与官方文档的测试资质表（免费测试：版号不要求）及"无内购无需版号"直接矛盾**。该站点以售卖资质代办为业，有商业动机，**建议不采信**
- TapTap 社区某帖称"个人小游戏一律需企业 + 版号"——**与官方前置备案"开发者认证主体为个人身份"条款矛盾**，同属代办口径

**处置：以 developer.taptap.cn 官方文档为准，但仍用邮件向官方书面复核**（问题清单见 §9）。

### 需平台确认、不采信亦不否认
无版号可开放下载的人数上限 / 测试时长上限 / 是否强制删档（第三方称 2 万人 / 180 天 / 须报备，官方文档未见）；个人主体结算开票方式（官方结算流程要求上传发票、结算单盖公章，个人如何执行未明）。

## 4. 软著：现在是硬门槛，且必须提前启动

- 【官方】内容规范列明需提供软著；前置备案要求填写"软件著作权人"
- 【第三方】接入 TapADN 广告 SDK **必须提交软著**，申请周期约 1 个月
- **判定：走 IAA 即视为硬性门槛**
- 办理主体（个人能否申请）与费用量级：**需核实，不预测**
- **【建议】启动时间点：Demo 玩法定型当天**，与 MVP 并行——它同时卡住前置备案与广告 SDK 两处

## 5. 商业化天花板与版号触发点

收入 = DAU × 人均日观看次数 × eCPM ÷ 1000。**eCPM 与留存本项目尚未实测，不预测。**

【推断】单机重度经营的 IAA 天花板低于轻度休闲矩阵：20~40 分钟 session 本应利好插屏，但自限 ≤5 次/日、且经营类缺乏"复活 / 翻倍"这类高频点位，曝光量受限。

**必须补版号的触发点**：开启任何内购 / 付费解锁；或平台要求不限量正式运营提供版号。
**个人开发者无法自行申请版号（多来源一致）**——现实路径只有注册公司，或与有版号资质的发行商合作，周期 4~12 个月。

## 6. 技术侧：一份代码多端

【推断】复用率：核心逻辑 / 数值 / UI / 配置表 **85~90%**；适配层 5~8%；构建配置 5%。
必然分叉：登录、存档、支付、广告、分享、统计、文件 IO。

**抽象层接口（AI 生成实现 + 自检页逐项亮灯，零基础唯一可靠验收手段）**：
`IPlatform`（boot / getRuntimeInfo / restart）、`IAccountService`、`ISaveService`、`IComplianceService`（实名与防沉迷）、`IAdService`、`IPayService`（MVP 用 NoOp）、`IShareService`、`IMetricsService`、`ISelfTest`。
按运行时产出 `WebAdapter / WechatAdapter / TapMiniAdapter / AndroidAdapter`；**禁止业务层直写 `wx.` `tap.` 或 native bridge**。

**包体纪律**：走 TapTap 小游戏则 §4MB 级纪律**全部保留**（图集上限、音频短循环、分包、索引色、UI 压缩）。仅当最终走 APK 才可放宽（图集 2048、音频直打进包、不做分包），但仍需保留冷启 ≤3s 与内存峰值预算。

【建议】SDK 先全用 NoOp 存根跑通玩法，最后再接。

## 7. 修订排期

| 路径 | 相对基准（45~60 周） | 结果 |
|---|---|---|
| **TapTap 小游戏首发** | **−2 ~ −4 周** | **41~56 周** |
| 原生 APK 首发 | +6 ~ +9 周 | 51~69 周（不含资质等待） |
| 微信首发（原基准） | 基准 | 45~60 周 |

TapTap 小游戏省：微信 SDK/支付/关系链 1~2W、微信侧分包调优 0.5~1W；加：Tap 转换插件 0.5W、合规材料与防沉迷自证 1W。

⚠️ 口径提醒：member-5 本周按 50h × 0.7 有效系数 = **4.4 人日/周**计算，与上一轮 7 人日/周不同。**两版口径并存是排期的主要不确定性**，建议以你实际跑满一个月后的产出重新校准一次。

## 9. 必须你亲自向 TapTap 官方书面确认的 8 个问题

1. 克苏鲁 / 深海悬疑题材，若商店页与宣传不使用"恐怖"字样、玩法为经营 + 塔防，是否仍会被判"以恐怖为核心题材"驳回？有无类目先例？
2. **个人开发者（无企业主体）能否完成小游戏前置备案并正式上线（试玩版）？是否需要营业执照？**
3. 无版号小游戏能否不限量开放下载？人数上限、测试时长上限、是否强制删档——请书面答复
4. 无版号状态下开放 IAA（激励视频）是否允许？是否必须先完成前置备案 + 软著？测试期是否绝对禁止广告位？
5. 个人主体如何完成 Dirichlet 结算（发票 / 结算单盖章）？
6. AI 生成美术：上架审核是否需提交标识材料与生成日志？包体元数据是否需加隐式标识？
7. 官方测试资质表（免费测试免版号）是否适用于手机 / Tap 小游戏，还是仅适用 PC 端？
8. 尸体 / 骷髅 / 触手在**像素风格化**表现下的判定尺度（是否接受剪影 / 非写实处理）？
